# ArcaGuard 단계별 개발 계획

현재 승인 범위: **Phase 1 읽기 전용 구조 조사**. Phase 0과 추가 UI 보완은 완료됐다.
추가로 승인된 UI 보완은 버튼 이동/고정/숨김과 복구 가능한 관리자 화면 설정에 한정한다.
이 범위는 구현했으며 Phase 5의 일반 운영 설정까지 승인/완료된 것은 아니다.
이 문서는 후속 작업 계획이며 구현 완료를 뜻하지 않는다.
도구 정책과 현재 연결 상태는 [TOOLING.md](TOOLING.md)를 따른다.
도구/Skill 추가는 해당 Phase 승인과 필요성이 확인된 뒤 진행한다.
테스트 범위와 신고/복수 관리자 계약은 [OPERATING_REQUIREMENTS.md](OPERATING_REQUIREMENTS.md)를 따른다.
운영 채널/이동 대상 탭은 사용자가 채널별로 선택/변경한다.
`prlvate`와 `TEST`는 미검증 개발 테스트 예시이며 등록값/전역 기본값으로 고정하지 않는다.
사용자 정의 광고/비광고 주제·예외·이미지 링크 계약은 [TOPIC_POLICIES.md](TOPIC_POLICIES.md)를 따른다.
백그라운드 이동과 관리자 사용 방해 금지는 `OPERATING_REQUIREMENTS.md` OP-07의 필수 조건이다.
Phase 1에서 검증된 비동기 요청/재조회 가능성을 조사하고, 불가능하면 자동 이동을 보류한다.
Phase 4/6/8은 제한된 감시·분석 부하, Phase 5는 조용한 안내 기본값을 적용한다.
Phase 7/9는 화면 전환 없는 이동, 입력·포커스·스크롤 보존, 정지/재개와 부하를 `BKG-*`로 검증한다.

- 도구: 기존 파일/명령 실행, npm, Vite, ESLint, Vitest. 추가 MCP/프로젝트 Skill 없음.
- 기존 폴더/Git 상태 확인 및 파일 보존.
- Vite, vite-plugin-monkey, Vitest, ESLint 구성.
- 루트/사이트 어댑터 AGENTS.md와 문서 및 기본 계층 디렉터리 생성.
- Korean UI 버튼, 격리된 테스트 패널, 로컬 미리보기.
- 완료 기준: install, dev, lint, test, build 성공 및 `.user.js` 생성.
- 관리자 API 호출, 사이트 데이터 수집 및 실제 게시글 변경 없음.

## Phase 1 — 아카라이브 구조 조사 (승인됨 / 진행 중)

1차 기록: 공개 참고 구현 조사와 사용자 제공 신고 목록/상세 필드 확인을 수행했다.
현재 DOM/채널별 권한/목록 완전성/TEST 탭/백그라운드 이동 경로는 미검증이며 Phase 1 전체 완료가 아니다.
구체적 근거와 미확인 항목은 `SITE_VERIFICATION.md`의 REF/USR-REPORT 기록을 따른다.

- 도구: 가능하면 Chrome DevTools MCP, `arcaguard-site-audit` Skill 도입.
  기존 브라우저 도구로 충분하면 재사용하고, Playwright MCP는 탐색상 필요할 때만 선택.
- ArcaRefresher 참고 및 승인된 공개 게시글/댓글/이미지 DOM 조사.
- 관리자 UI, 신고 사유/수/목록, 권한, 글머리 UI의 접근 가능성 조사.
- 사이트 신고 알림→상세 링크/유형/신고자별 사유의 실제 구조, 알림 수신 완전성과 상세 읽기의 부작용 조사.
  알림 자동 클릭/모두 읽기/처리 상태 변경으로 조사하지 않는다.
- 신고 대상 링크/신고자 이름/안정적 계정 ID/신고 내용, 목록 완전성, 글머리 ID와
  타 관리자 이동/처리 이력 확인 가능 여부 조사. 이름만으로 계정 고유성을 추정하지 않음.
  안정적 계정 ID는 제공될 경우의 참고 필드이며 사이트 총수 사용의 필수 조건은 아니다.
- TEST 생성·관리자 전용 설정 완료의 사용자 확인을 반영한다.
  실제 ID/본문 보존/접근 제한/삭제 상태 구분은 직접 검증 전이며 수동 변경 동선은 수정 → 글머리 선택 → 저장이다.
- 출처/날짜가 있는 선택자와 공개 읽기 테스트, 미확인 기능 Mock.
- 게시물 내용의 클릭 가능한 이미지/실제 링크 href와 표시 이미지 URL을 구별해 조사.
  이미지 확대/지연 로딩/동적 클릭 동작과 일반 링크의 차이를 기록하며 직접 목적지를 열지 않는다.
- 후기형 홍보의 보조 신호인 작성글 수는 실제 제공 여부/전체·채널 범위/현재 글 포함/누락 가능성을 조사한다.
  참고 구현의 최근 목록/15개 이상 표시는 전체 이력 근거가 아니며 계정 생성 시각이나 정확한 0건으로 추정하지 않는다.
- 완료 기준: 검증 근거와 미검증 경계 기록. 쓰기 연동 금지.

### 현재 수행 순서와 마무리 조건 (2026-10-24 갱신)

현재 판정은 **자료·설계 정리 완료 / 실사이트 읽기 검증 미완료 / Phase 1 진행 중**이다.
원시 근거는 SITE_VERIFICATION의 USR/REF/PLATFORM/TOOL 기록에 두고 이 절은 작업 순서를 관리한다.

2026-10-25 요청한 DOM/알림 수신/백그라운드 글머리 이동/선택적 신고 완료의 현재 판정은
SITE_VERIFICATION CHECK-01~04를 따른다. 일반 플랫폼 지원은 확인했지만 운영 기능은 미구현이며
실사이트 접근 제한 해제 근거/권한·요청 검증 없이 성공을 선언하거나 쓰기 시험으로 넘어가지 않는다.

1. **기존 근거 일치시키기 — 이번 정리 완료.** 신고 목록/상세 필드, 사이트 수와 1회 제한,
   TEST 설정 완료, 수정 동선, 신고 완료와 글 이동 분리, 버튼 지정 답변을 기준으로 현재 문서를 맞춘다.
   이를 이미 아는 질문/새로운 실사이트 검증으로 다시 세지 않는다.
2. **사용자 제공 정보 보완 — 요청 자료 확보.** 목록의 전체/이전 내역 조회/대기 목록/완료 목록,
   글머리 선택의 일반/TEST 화면을 받았다(USR-REPORT-06, USR-CATEGORY-03).
   알림은 직접 눌러야 읽음 처리된다는 답변도 확보했다. 같은 사진/설명을 다시 요청하지 않는다.
   화면 자료는 사용자 관측 근거이며 실제 URL·커서/필드 식별값/권한/저장 요청까지 검증한 것은 아니다.
3. **접근 제한의 진단 결과 유지 — 도구 외부 해결이 필요한 항목.** 기존 오류는 site-safety 단계에서
   승인창/Auto-review 이전에 거부됐고 사용자는 차단 목록에 없다고 확인했다(TOOL-01).
   내부 차단 이유/해제 가능 여부는 미확인이다. 문제 신고를 실제로 제출했다고 표시하지 않으며
   재접속/새 브라우저·MCP/원시 요청으로 우회하지 않는다.
4. **허용된 현재 읽기 근거 확보 — 미완료.** 사이트 접근이 허용되는 환경에서 현재 목록·상세 필드,
   글머리 ID/글 상태/채널별 권한, 본문·댓글 경계/이미지 href 관계를 읽기 전용으로 확인해야 한다.
   출처·날짜·범위·누락/오류 상태를 기록하고 최소 익명 자료로 읽기 검증을 한다.
   버튼/신고 분류의 ID와 실제 지정 답변·효과도 게시글 이동 대상과 따로 조사한다.
5. **무방해 읽기 가능성 정리 — 미완료.** 읽음/신고 처리 상태가 변하지 않는지, 추가 이미지·프레임 요청이나
   화면/포커스/입력 변화가 없는지를 확인한다. 글 이동/신고 제출은 관찰 가능한 필드·권한과 미확인 효과만 기록한다.
   요청을 보내거나 숨겨진 인증 값·토큰을 수집해 동작을 알아내지 않는다.
   Chrome 로컬 합성 읽기 실험 3경로의 무요청/실행 없음/화면 상태 보존은 PLATFORM-03에 기록했다.
   실제 사이트 부작용/큰 입력/CSP/IME/정지·재개는 미검증이며 전체 읽기 지원 완료는 아니다.
6. **단계 검토 보고 — 이후 수행.** 지원 가능한 읽기 항목의 실제 근거/검증 결과와 미지원·불명확 항목을
   명시하고 lint/test/build 및 출처·문서 일치를 확인한다. 실제 근거가 없는 기능을 완료로 표시하지 않는다.
   현재 직접 DOM/권한/읽기 경로가 미검증이므로 Phase 1 전체 완료를 선언하지 않는다.

지금 추가할 필요가 없는 항목: 신고자 중복 집계 장부, 채널/탭 기본값 하드코딩, 새 MCP/유료 서비스,
광고 사례 추가 수집이나 임계값 N의 최종 확정. 현재 설정 UI는 외형 설정만 구현돼 있다.
후속 구현은 순수 탐지 Phase 2~3, 신고 감시 Phase 4, 설정 UI Phase 5, OCR/QR Phase 6,
실제 이동·신고 제출/부분 실패 Phase 7, 로컬 AI Phase 8, 통합·성능 Phase 9로 둔다.
이 정리는 후속 Phase 승인이나 단일 글 이동/신고 제출/작성자 통지 승인이 아니다.

### 참고 소스를 현재 화면 요구에 연결한 우선순위 (설계 / 미구현)

2026-10-24 ArcaRefresher 추가 조사 REF-09~12를 반영했다. 현재 화면의 근거는 사용자 제공 사진이며
실시간 페이지를 직접 확인했다는 의미가 아니다. 다음 항목은 기존 Phase에 배치할 설계이지 새 구현 승인이 아니다.

1. **페이지·채널 구분:** 신고 목록/상세/게시글/편집 화면을 구별하고 설정 채널·신고 대상 링크와 대조한다.
   로그인 표시/구독 채널 메뉴/페이지 로드 완료를 관리자 권한으로 사용하지 않는다. 권한은 읽기/이동/신고 제출별로 확인한다.
2. **신고 목록:** 대기/완료/이전 내역의 실제 범위를 확인한다. 목록 행 수와 대상 신고 수를 구별하고
   필드 누락/조회 오류/권한 미확인을 0건이나 정상 완료로 바꾸지 않는다. 노드 교체 시 기존 읽기 상태를 무효화한다.
3. **신고 상세:** 현재 총수·사유·대상·처리 상태를 묶어 읽고 신고 완료와 글 이동 상태를 별도 표시한다.
   처리 버튼/답변 프리셋은 글머리와 독립이며 이름·색·취소선만으로 서버 효과를 판정하지 않는다.
4. **글 편집:** 일반/TEST의 실제 식별값·접근 제한·본문 보존·저장 의미를 검증한다.
   편집 화면을 자동 조작하지 않고 별도 승인 단계에서 검증된 백그라운드 경로의 지원 여부를 판정한다.
5. **사용 중 감시:** 화면 목록 교체 없이 채널별 제한 큐로 읽고, 느린 한 조회 주기가 끝나기 전에 같은 조회를 겹쳐 시작하지 않는다.
   알림/반복 신호는 제한된 재대조 요청으로 합친다. 숨김 상태와 실행 불가 상태를 구별하고 재개 시 최신 정보를 읽는다.
6. **설정·상태:** 허용 스키마/버전/채널 검증, 안전한 OFF 복원, 현재 인스턴스의 즉시 중지,
   실행 직전 버전 확인을 요구한다. 탭 간 변경 신호를 검증하며 관리 실행 지시/다른 계정·PC의 잠금으로 사용하지 않는다.
   가져오기 후 현재 작성 화면을 새로고침하지 않고 필요한 상태는 ArcaGuard 자체 화면에 조용히 표시한다.

읽기·감시 항목은 Phase 4, 설정은 Phase 5, 실제 조치/경합은 Phase 7, 통합·공존 부하는 Phase 9에서 검증한다.
현재 Phase 1에서는 현재 DOM/필드/권한·부작용 근거의 공백을 기록한다. 확보한 사진을 다시 요청하거나
참고 소스의 일반 게시판 주기·페이지 번호·사용자 스타일을 신고 화면의 검증값으로 재사용하지 않는다.

## Phase 2 — 기본 규칙·주제 탐지 (미승인)

- 도구: Vitest/ESLint. 반복되는 탐지 검증이 생기면 `arcaguard-evasion-tests` Skill 도입.
- 실행 제한이 있는 정규식 엔진/Worker, 규칙 검증, 가중치/제외 규칙/점수.
- 원문 테스트 도구와 근거 출력. 점수는 확률로 표시하지 않음.
- 광고/비광고 주제별 규칙·예외·점수·출처 계약과 Mock URL/이미지 링크 입력 검증.
- 예외 우선 평가, 주제 간 점수 비합산, 동일 원천 근거 중복 가산 방지.
- 완료 기준: 광고/인용/경고/정상 문장 테스트, 잘못된 정규식 및 제한 시간 검증.

## Phase 3 — 우회 문자 탐지 (미승인)

- 도구: Vitest + `arcaguard-evasion-tests`. 성능 문제가 확인되면 프로파일러 선택.
- 제한된 노이즈 구간 정규화, 한글 자모 분해/가중 유사도, 후보/횟수/길이 제한.
- 완료 기준: `대@414출@$15권@$5유`, `떄출꿘유` 탐지 후보와 정상 문장/성능 테스트.
- 유사도 결과만으로 자동 이동 금지.

## Phase 4 — 신고 감시 (미승인)

- 도구: 검증된 읽기용 브라우저 도구와 Mock 데이터. 필요 시 Playwright MCP 선택.
  신고/권한 안전 검증이 반복되는 이 단계부터 `arcaguard-moderation-safety` Skill 도입.
- 검증된 신고 읽기, 호출어/전체 신고 수/호출 신고 수, 읽기 전용 게시글 수집.
- 중복 방지, 스케줄러/백오프, 댓글과 게시글 구분.
- 사이트 신고 알림 후보 큐와 같은 채널/신고 이벤트 중복 억제, 알림 OFF/누락 시 허용된 목록 대조.
  현재 창을 이동시키거나 읽음 상태를 대신 변경하지 않는 검증된 읽기 경로만 사용한다.
- 내용의 `광고` 포함 검사, 사이트 현재 신고 수/사유 스냅샷 사용, 재수집 시 덧셈 없음.
  사이트 자체의 1회 신고 제한을 사용하고 별도 신고자 중복 집계는 구현하지 않는다.
- 필수 신고 필드/현재 사이트 수/사유 읽기가 미확인이면 자동 처리 차단.
- OP-10 조치 정책에 맞춰 신고 수와 호출 사유 수를 분리하고 AI 정책의 호출어 비필수 조건을 보존한다.
  정책 자격/내용 분류/실제 조치 성공을 구별하며 이 단계에서는 이동을 실행하지 않는다.
- 검증된 게시물 수집에 일반/이미지 링크 목적지를 포함하고 주제별 신고 호출 조건을 연결.
- 완료 기준: 조건 충족 신고만 분석. 신고 자료가 없으면 Mock만 사용.

## Phase 5 — 관리자 설정 UI (미승인)

- 도구: Playwright Test로 결정적 UI 자동 테스트. 대화형 탐색에는 필요 시 Playwright MCP.
- 대시보드, 독립 채널 설정, 신고/탐지/모드/알림 설정, 규칙 테스트, 처리 기록.
- 버전 스키마, 검증/마이그레이션, GM 런타임 저장 어댑터, JSON 내보내기/가져오기.
- 사용자가 선택한 채널/대상 탭의 등록·변경·삭제, 사이트 총수/키워드 포함 사유 수/검증 상태 구별,
  관찰 모드 및 이미 처리/타 관리자 이동 사유 표시. 설정 가져오기로 자동 조치 활성화 금지.
- 완료 기준: 영구 저장/채널 격리, 손상 설정 복구, 가져오기 시 자동 조치 비활성화.
- 주제/규칙/예외의 추가·수정·삭제·토글, 출처별 검사와 호출어/처리 모드/대상 상속·선택 UI.
- 주제/예외 설정 변경 시 대기 작업 재검토와 복수 주제 대상 충돌의 검토 표시.
- 신고 기준 이동/AI 확인 후 이동의 단일 선택, N/K, 채널·주제 상속과 실행 모드의 독립 설정.
  미지정/손상/가져오기로 자동 실행 금지, AI 미준비 표시, 정책 변경 시 대기 작업 무효화 (`MODE-*`).
- OP-11 신고 카테고리/처리 버튼·답변·작성자 통지 설정. 사이트의 현재 선택지를 사용하고
  게시글 이동 대상과 구별한다. 제출/작성자 통지는 기본 OFF이며 UI 자체는 실제 관리 쓰기를 수행하지 않는다.

## Phase 6 — 이미지 분석 (미승인)

- 도구: Vitest와 개인정보를 제거한 이미지 Fixture. 이미지 접근 진단에 브라우저 도구 선택.
- Tesseract.js 한국어/영어 OCR, 별도 QR 모듈, 캐시/이미지 개수/크기/시간 제한.
- 허용된 CORS/CSP/Userscript 접근만 사용.
- 이미지 DOM 링크와 OCR/QR 결과를 출처별로 결합. OCR/QR OFF도 이미지 링크 검사는 가능해야 함.
- 완료 기준: 기능 토글, 이미지 광고/정상 차트/실패 처리 검증. 유료 API 없음.

## Phase 7 — 관리자 글머리 변경 (미승인, 별도 승인 필수)

- 도구: `arcaguard-moderation-safety` Skill과 Mock 테스트.
  지정 테스트 글과 별도 승인이 있을 때만 실사이트 브라우저 검증.
- 실제 관리자 UI와 글머리 이동/휴지통 의미 검증 후 시작.
- 채널별 권한 재검사, 최신 상태/대상 확인, 시뮬레이션 및 승인된 단일 테스트 글 이동.
- 결과 재조회, 상태 전환, 다중 탭 중복 방지, 긴급 중지, 로그/알림.
- 이미 설정된 대상/확인된 처리 완료 대상은 건너뛰고 다른 관리자의 이동을 덮어쓰지 않는다.
- 채널/대상 설정 변경 시 대기 작업 취소/재검토 및 이동 직전 설정 버전 재검증.
- 주제별 예외가 자동 이동을 차단하는지, 복수 주제 충돌 시 검토/같은 대상이면 단일 조치인지 검증.
- 다중 계정/PC의 경합과 불명확 응답을 검증한다. 사이트 조건부 변경이 미지원이면
  자동 실행 담당 인스턴스 1개와 나머지 관찰 모드를 검토하되 완전한 원격 잠금으로 설명하지 않는다.
- 완료 기준: 이동 후 검증, 권한/변경/실패 시 차단, 중복 조치 방지. 삭제/차단 없음.
- 모든 조건을 검증하기 전 자동 이동 비활성화.
- OP-10 두 정책의 자격을 공통 안전 검증에 연결한다. A는 내용 광고 분류 없이 신고 조건으로,
  B는 검증된 현재 AI 양성으로 자격을 계산한다. B는 Phase 8 모델 검증 전 실행 불가다.
- OP-11의 별도 신고 제출은 실제 효과에 삭제/차단이 없고 권한·배경 경로·결과 조회가 검증된 경우만 연결한다.
  기본 순서인 이동 검증 후 신고 제출, 독립 상태/부분 실패/타 관리자 답변 보존을 Mock부터 검사한다.
  실제 신고 제출도 별도 쓰기 승인이 필요하며 버튼 이름이나 빈 미리보기로 안전을 추정하지 않는다.

## Phase 8 — 선택적 무료 로컬 AI (미승인)

- 도구: 한국어 모델 검증 테스트와 성능 측정. 필요 시 브라우저 진단 도구.
- 한국어 성능/브라우저 호환성 평가 후 무료 모델 연결.
- 출처/용량/설치 상태 표시, 로컬 로딩/타임아웃/민감도, 실패 시 안전한 처리.
- 완료 기준: AI OFF에서도 기본 기능 작동, 외부 전송 없음. 적합 모델 없으면 실험적 유지.
- AI 확인 정책의 광고/비광고/판단 불가/오류 계약, 모델별 한국어 판정 기준과 내용 지문 연결을 검증한다.
  AI 실패 시 A로 자동 전환하지 않으며 A는 AI 없이 사용 가능하다. 자동 이동은 계속 Phase 7 안전 계약을 따른다.
