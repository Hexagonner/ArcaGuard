# ArcaGuard 단계별 개발 계획

현재 승인 범위: **Phase 0만 승인됨**. 단계 완료 후 중단한다.
이 문서는 후속 작업 계획이며 구현 완료를 뜻하지 않는다.
도구 정책과 현재 연결 상태는 [TOOLING.md](TOOLING.md)를 따른다.
도구/Skill 추가는 해당 Phase 승인과 필요성이 확인된 뒤 진행한다.
테스트 범위와 신고/복수 관리자 계약은 [OPERATING_REQUIREMENTS.md](OPERATING_REQUIREMENTS.md)를 따른다.
운영 채널/이동 대상 탭은 사용자가 채널별로 선택/변경한다.
`prlvate`와 `TEST`는 미검증 개발 테스트 예시이며 등록값/전역 기본값으로 고정하지 않는다.
사용자 정의 광고/비광고 주제·예외·이미지 링크 계약은 [TOPIC_POLICIES.md](TOPIC_POLICIES.md)를 따른다.

## Phase 0 — 프로젝트 초기화

- 도구: 기존 파일/명령 실행, npm, Vite, ESLint, Vitest. 추가 MCP/프로젝트 Skill 없음.
- 기존 폴더/Git 상태 확인 및 파일 보존.
- Vite, vite-plugin-monkey, Vitest, ESLint 구성.
- 루트/사이트 어댑터 AGENTS.md와 문서 및 기본 계층 디렉터리 생성.
- Korean UI 버튼, 격리된 테스트 패널, 로컬 미리보기.
- 완료 기준: install, dev, lint, test, build 성공 및 `.user.js` 생성.
- 관리자 API 호출, 사이트 데이터 수집 및 실제 게시글 변경 없음.

## Phase 1 — 아카라이브 구조 조사 (미승인)

- 도구: 가능하면 Chrome DevTools MCP, `arcaguard-site-audit` Skill 도입.
  기존 브라우저 도구로 충분하면 재사용하고, Playwright MCP는 탐색상 필요할 때만 선택.
- ArcaRefresher 참고 및 승인된 공개 게시글/댓글/이미지 DOM 조사.
- 관리자 UI, 신고 사유/수/목록, 권한, 글머리 UI의 접근 가능성 조사.
- 신고 대상 링크/신고자 이름/안정적 계정 ID/신고 내용, 목록 완전성, 글머리 ID와
  타 관리자 이동/처리 이력 확인 가능 여부 조사. 이름만으로 계정 고유성을 추정하지 않음.
- 출처/날짜가 있는 선택자와 공개 읽기 테스트, 미확인 기능 Mock.
- 게시물 내용의 클릭 가능한 이미지/실제 링크 href와 표시 이미지 URL을 구별해 조사.
  이미지 확대/지연 로딩/동적 클릭 동작과 일반 링크의 차이를 기록하며 직접 목적지를 열지 않는다.
- 완료 기준: 검증 근거와 미검증 경계 기록. 쓰기 연동 금지.

## Phase 2 — 기본 규칙·주제 탐지 (미승인)

- 도구: Vitest/ESLint. 반복되는 탐지 검증이 생기면 `arcaguard-evasion-tests` Skill 도입.
- 실행 제한이 있는 정규식 엔진/Worker, 규칙 검증, 가중치/제외 규칙/점수.
- 원문 테스트 도구와 근거 출력. 점수는 확률로 표시하지 않음.
- 광고/비광고 주제별 규칙·예외·점수·출처 계약과 Mock URL/이미지 링크 입력 검증.
- 예외 우선 평가, 주제 간 점수 비합산, 동일 원천 근거 중복 가산 방지.
- 완료 기준: 광고/인용/경고/정상 문장 테스트, 잘못된 정규식 및 제한 시간 검증.

## Phase 3 — 우회 문자 탐지 (미승인)

- 도구: Vitest + `arcaguard-evasion-tests`. 성능 문제가 확인되면 프로파일러 선택.
- 제한된 노이즈 구간 정규화, 한글 자모 분해/가중 유사도, 후보/횟수/길이 제한.
- 완료 기준: `대@414출@$15권@$5유`, `떄출꿘유` 탐지 후보와 정상 문장/성능 테스트.
- 유사도 결과만으로 자동 이동 금지.

## Phase 4 — 신고 감시 (미승인)

- 도구: 검증된 읽기용 브라우저 도구와 Mock 데이터. 필요 시 Playwright MCP 선택.
  신고/권한 안전 검증이 반복되는 이 단계부터 `arcaguard-moderation-safety` Skill 도입.
- 검증된 신고 읽기, 호출어/전체 신고 수/호출 신고 수, 읽기 전용 게시글 수집.
- 중복 방지, 스케줄러/백오프, 댓글과 게시글 구분.
- 내용의 `광고` 포함 검사, 대상별 고유 신고자/호출 신고자 집계, 재수집/재시작 멱등성.
- 필수 신고 필드나 고유성/현재 집계가 미확인이면 자동 처리 차단.
- 검증된 게시물 수집에 일반/이미지 링크 목적지를 포함하고 주제별 신고 호출 조건을 연결.
- 완료 기준: 조건 충족 신고만 분석. 신고 자료가 없으면 Mock만 사용.

## Phase 5 — 관리자 설정 UI (미승인)

- 도구: Playwright Test로 결정적 UI 자동 테스트. 대화형 탐색에는 필요 시 Playwright MCP.
- 대시보드, 독립 채널 설정, 신고/탐지/모드/알림 설정, 규칙 테스트, 처리 기록.
- 버전 스키마, 검증/마이그레이션, GM 런타임 저장 어댑터, JSON 내보내기/가져오기.
- 사용자가 선택한 채널/대상 탭의 등록·변경·삭제, 원시 신고 수/고유 신고자 수/검증 상태 구별,
  관찰 모드 및 이미 처리/타 관리자 이동 사유 표시. 설정 가져오기로 자동 조치 활성화 금지.
- 완료 기준: 영구 저장/채널 격리, 손상 설정 복구, 가져오기 시 자동 조치 비활성화.
- 주제/규칙/예외의 추가·수정·삭제·토글, 출처별 검사와 호출어/처리 모드/대상 상속·선택 UI.
- 주제/예외 설정 변경 시 대기 작업 재검토와 복수 주제 대상 충돌의 검토 표시.

## Phase 6 — 이미지 분석 (미승인)

- 도구: Vitest와 개인정보를 제거한 이미지 Fixture. 이미지 접근 진단에 브라우저 도구 선택.
- Tesseract.js 한국어/영어 OCR, 별도 QR 모듈, 캐시/이미지 개수/크기/시간 제한.
- 허용된 CORS/CSP/Userscript 접근만 사용.
- 이미지 DOM 링크와 OCR/QR 결과를 출처별로 결합. OCR/QR OFF도 이미지 링크 검사는 가능해야 함.
- 완료 기준: 기능 토글, 이미지 광고/정상 차트/실패 처리 검증. 유료 API 없음.

## Phase 7 — 관리자 글머리 변경 (미승인, 별도 승인 필수)

- 도구: `arcaguard-moderation-safety` Skill과 Mock 테스트.
  지정 테스트 글과 별도 승인이 있을 때만 실사이트 브라우저 검증.
- 실제 관리자 UI와 글머리 이동/휴지통 의미 검증 후 시작.
- 채널별 권한 재검사, 최신 상태/대상 확인, 시뮬레이션 및 승인된 단일 테스트 글 이동.
- 결과 재조회, 상태 전환, 다중 탭 중복 방지, 긴급 중지, 로그/알림.
- 이미 설정된 대상/확인된 처리 완료 대상은 건너뛰고 다른 관리자의 이동을 덮어쓰지 않는다.
- 채널/대상 설정 변경 시 대기 작업 취소/재검토 및 이동 직전 설정 버전 재검증.
- 주제별 예외가 자동 이동을 차단하는지, 복수 주제 충돌 시 검토/같은 대상이면 단일 조치인지 검증.
- 다중 계정/PC의 경합과 불명확 응답을 검증한다. 사이트 조건부 변경이 미지원이면
  자동 실행 담당 인스턴스 1개와 나머지 관찰 모드를 검토하되 완전한 원격 잠금으로 설명하지 않는다.
- 완료 기준: 이동 후 검증, 권한/변경/실패 시 차단, 중복 조치 방지. 삭제/차단 없음.
- 모든 조건을 검증하기 전 자동 이동 비활성화.

## Phase 8 — 선택적 무료 로컬 AI (미승인)

- 도구: 한국어 모델 검증 테스트와 성능 측정. 필요 시 브라우저 진단 도구.
- 한국어 성능/브라우저 호환성 평가 후 무료 모델 연결.
- 출처/용량/설치 상태 표시, 로컬 로딩/타임아웃/민감도, 실패 시 안전한 처리.
- 완료 기준: AI OFF에서도 기본 기능 작동, 외부 전송 없음. 적합 모델 없으면 실험적 유지.

## Phase 9 — 안정화 및 배포 (미승인)

- 도구: `arcaguard-release-check` Skill, Git. Issues/PR 협업을 도입할 때 기존 GitHub 연결 우선.
- 통합/오탐/권한/다중 채널/다중 탭/DOM 변경/마이그레이션/성능 검증.
- 설치/업데이트 가이드, 알려진 제한, 배포 `.user.js`와 라이선스.
- 로그 정리/재시작 후 재집계/기처리 방지, 복수 관리자/PC 경합 회귀와 개인정보 보관 검증.
- 사용자 정의 주제/예외 격리, 이미지 링크 오탐과 근거 중복, 정책 버전 변경의 회귀 검증.
- 완료 기준: 주요 시나리오 및 안전장치 검증, 문서와 실제 구현 일치.

## 각 단계 공통 완료 보고

`docs/PHASE_STATUS.md`에 구현된 기능, 파일 변경 이유, 명령/결과,
미검증 사항, 발견 문제, 설계 변경, 다음 단계 요약을 기록한다.
후속 단계는 승인 전 시작하지 않는다. 실사이트 테스트는 추가 승인을 받는다.
MCP 연결 불가 시 가능한 로컬 개발/Mock 검증은 계속하되 실제 관리자 연동은 미검증으로 남긴다.
