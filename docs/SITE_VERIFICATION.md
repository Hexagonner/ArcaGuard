## TOOL-01 — 기존 사이트 접근 실패 원문 재확인

2026-10-24 같은 대화의 기존 브라우저 실패 기록을 다시 읽었다. 차단 대상에 재접속한 것은 아니다.

- 원문: `The site-safety policy blocks this action; no user permission prompt or Auto-review was attempted.`
- https://arca.live의 site-safety 단계에서 관측 권한을 얻지 못했다는 도구 응답이다.
  일반 연결 실패/로그인 실패/채널 관리자 권한 부족으로 재분류할 근거는 없다.
- 사용자가 브라우저 관리의 차단 목록에 해당 사이트가 없음을 확인했다. 출처는 사용자 진술이다.
  사용자 차단 목록과 같은 것이라고 단정하거나 삭제할 항목이 있다고 안내하지 않는다.
- 내부 차단 규칙/오탐 여부/정책 변경 가능 여부는 응답에 나타나지 않아 미확인이다.
  사용자 승인창이나 Auto-review 거절을 해소하면 해결된다고 설명하지 않는다.
- 실제 Chrome localhost UI 접근 성공과 사이트별 접근 거절은 별도로 기록한다.
  이후 다른 도구/브라우저/원시 요청/프록시로 차단된 관측을 대신 수행하지 않았다.
- 지원 진단이 필요한 외부 제약으로 남긴다. 사용자에게 문제 신고 방법은 안내했지만
  피드백/지원 요청을 실제 제출하거나 차단 해제를 수행한 것은 아니다.

## Phase 1 마무리에 필요한 근거와 후속 단계 경계

2026-10-24 재점검. 이미 제공된 신고 열/상세 사유/총수/1회 제한/수동 수정 순서는 다시 요구하지 않는다.

- **신고 읽기:** 현재 목록·상세의 필드 경계와 대상 대응, 목록 페이지/더 보기/필터 및 읽은 범위를
  확인해야 한다. 사용자에게 보이는 페이지/필터 이름을 질문했다. 한 건만 있는 화면에서 목록 완전성을 추정하지 않는다.
- **읽음 부작용:** 상세를 직접 열기만 해도 알림이 읽음 처리되는지 사용자 답변 대기다.
  직접 열기와 비동기 읽기의 부작용이 같다고 추정하지 않는다. 안전한 배경 읽기 검증은 별도로 필요하다.
  알림을 클릭하지 않고 신고 목록을 읽는 경로도 독립적으로 권한/부작용을 확인해야 한다.
- **격리 대상:** 사용자가 TEST 생성/관리자 전용 설정 완료를 답했다(USR-CATEGORY-02).
  설정 완료의 출처는 사용자 확인이며 현재 목록 ID/실제 접근 제한/본문 보존/현재 상태는 직접 검증 전이다.
- **현재 사이트 구조:** 게시글/댓글 경계, 현재 분류·기처리 상태, 이미지 앵커 href와 파일 주소의 관계는
  참고 코드만 있고 직접 DOM 근거가 없다. 새로운 도구나 임의 선택자로 이 공백을 채우지 않는다.
- **무방해 경로의 조사 범위:** 수정 화면에서 글머리 선택이 가능하다는 사용자 설명은 확보했다.
  읽기 전용으로 확인 가능한 권한/필드 범위/변경 의미와 아직 확인할 수 없는 요청·경합 조건을 구분한다.
  실제 이동을 보내거나 숨겨진 인증 필드/비밀값을 수집하는 작업은 Phase 1 완료 조건으로 요구하지 않는다.
- 현재 브라우저 도구의 사이트 정책 차단으로 직접 DOM/권한/요청 근거는 확보하지 못했다.
  사용자 답변은 `user-provided`로 보완하되 직접 검증으로 바꾸지 않는다. 차단 대상 재시도/우회는 하지 않는다.
- **후속 검증:** 실제 한 글 이동/전후 결과/동시 편집 보호/화면 보존은 Phase 7,
  모델 설치·한국어 성능/AI 판정 기준은 Phase 8, 전체 통합·부하·복수 관리자 회귀는 Phase 9다.
  이 실행 검증을 하지 않았다는 이유만으로 Phase 1에 쓰기나 AI 구현을 끼워 넣지 않는다.
- 지금 신고 임계값 N을 확정하거나 광고 사례를 더 모으는 것은 조사 완료의 선행 조건이 아니다.
  두 정책/실패 시 처리 계약은 OP-10에 설계됐으며 구현 단계에서 사용자 설정을 지원한다.
