# 보안 및 안전 경계

현재 실행 코드는 UI/위치·표시 선호 저장/메뉴 등록만 사용하며 사이트 fetch/XHR이나 타이머 기반 감시는 없다.
배포 메타데이터는 HTTPS arca.live에만 적용되며 `GM_registerMenuCommand` 하나와 `@noframes`를 사용한다.
개발 서버는 루프백 127.0.0.1에서만 수신한다. 개발 스크립트는 배포본과 구별한다.
Shadow DOM은 스타일 격리 수단이며 보안 경계나 사이트의 접근 차단 기능이 아니다.

후속 구현 시: 채널별 권한 검증, Simulation 기본값, 자동 이동 OFF,
긴급 중지 및 실제 상태 재검증을 적용한다. 조치 자격은 OP-10의 선택 정책을 따른다.
신고 기준 정책은 키워드/사이트 총수로 격리 자격을 판단할 수 있지만 신고를 본문 광고 근거로 가산하지 않는다.
AI 확인 정책은 현재 글의 유효한 로컬 AI 판정을 요구하며 실패 시 신고 기준 정책으로 자동 전환하지 않는다.
관리자 권한 우회, 미확인 엔드포인트 추측, 자동 삭제/차단은 금지한다.
자격 증명을 저장하지 않고 게시글/신고를 외부 AI 서버에 전송하지 않는다.
불확실하거나 오류가 발생하면 관리자 조치를 중단한다.
UI 문자열은 textContent로 삽입한다. 외부 설정과 정규식은 후속 단계에서 검증한다.

추가 운영 계약은 `OPERATING_REQUIREMENTS.md`를 따른다. 신고자 이름과 내용은
검증/관리자 검토에 필요한 범위로 제한하고 기본 로그/내보내기에 자동 복사하지 않는다.
안정적 계정 식별값은 자격 증명과 구별하며, 이름만으로 계정을 추정하지 않는다.
사이트의 1회 신고 제한에 따라 별도 신고자 기여 장부는 만들지 않는다. 사이트 총수는 최신 값으로
교체하며 재조회 값을 더하지 않는다. 같은 작업의 재실행/기처리 재이동 방지는 유지한다.
Fixture는 합성 계정/신고를 사용한다. 보관 기한 만료로 중복 방지 상태를 재구성할 수 없으면
자동 처리를 중단한다. 다른 관리자의 작업을 덮어쓰지 않으며 다중 PC 잠금을 가정하지 않는다.

주제 추가는 자동 삭제/이용자 차단 권한을 만들지 않는다. 주제별 예외/호출 조건도 기존
신고/권한/기처리 검증을 우회하지 못한다. 예외 계산 실패나 정책 충돌 시 자동 조치는 중단한다.
이미지 링크는 게시물에서 읽을 뿐 외부 목적지 방문/다운로드/리다이렉트 추적/onclick 실행을 하지 않는다.
URL의 민감한 쿼리/인증 정보는 로그/내보내기에 복사하지 않는다. Fixture에는 합성 주소/내용을 사용한다.

후속 응답 파싱은 현재 페이지에 붙이지 않는 것 외에 추가 리소스 요청도 검증해야 한다.
분리된 DOMParser 문서에서도 이미지/프레임을 불러올 수 있다는 브라우저 문서 근거는
SITE_VERIFICATION PLATFORM-01에 기록했다. 외부 목적지/스크립트를 실행하지 않는 파싱을 검증하고,
실패하면 보류한다. CSP/Trusted Types 완화나 숨겨진 프레임으로 우회하지 않는다.
