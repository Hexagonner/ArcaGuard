# 검증 계획

## Phase 0

- `npm install`: 의존성 설치와 lockfile 생성.
- `npm run lint`: ESM/브라우저/Node 환경별 ESLint 검사.
- `npm run test`: UI 초기 닫힘, 중복 삽입 방지, 열기/닫기/Escape/포커스,
  안전 상태 표시 및 UI 확인 중 네트워크/저장소 호출 없음.
  승인된 위치 보완의 드래그/키보드/복원/초기화/경계/손상 자료/저장 차단도 포함한다.
- `npm run build`: 설치 가능한 단일 `.user.js` 번들 생성 및 메타데이터/구문 검사.
- `npm run dev`: 루프백 개발 서버와 로컬 미리보기/개발 스크립트 응답 확인.
- 로컬 브라우저에서 화면 열기/확인/닫기와 좁은 화면 확인.
- Tampermonkey 설치와 실제 arca.live 렌더링은 별도 검증 대상으로 기록한다.

## 후속 단계

REQUIREMENTS.md 11장의 단위/통합/오탐 시나리오를 각 기능 추가 시 구현한다.
특히 잘못된 정규식, 시간 초과, 우회 문자열과 정상 인용/경고, 손상 설정,
권한 실패/신고 누락/댓글 신고/대상 없음/기처리/상태 변경/다중 탭을 포함한다.
OCR/AI 비활성 및 오류, 다중 채널 격리, 글머리 변경 실패와 검증을 포함한다.
모든 관리자 쓰기는 Mock으로 검사하며 최초 실사이트 테스트는 승인된 읽기만 허용한다.
글머리 변경은 추가 승인과 지정 테스트 글 하나로 제한한다.

## 운영 보완 인수 시나리오 (미구현 / 아직 미실행)

기준: `OPERATING_REQUIREMENTS.md`. 아래 사례는 후속 Phase의 Mock/합성 데이터 테스트 계획이며,
현재 Vitest 18개에 이 기능들이 검증되어 있다고 해석하면 안 된다. A/B는 실제 이용자가 아닌 가짜 계정이다.
글/댓글 ID, 계정 식별값, TEST 글머리 ID도 합성 값으로 만들고 실사이트 ID를 추측하지 않는다.
아래 TEST 사례는 선택한 테스트 설정의 예시다. 공통 처리 로직은 사용자가 정한 채널/대상을 따른다.

### 신고 입력과 집계 — Phase 1 조사 후 Phase 4 구현

- **RPT-01 반복 신고:** 같은 대상에 계정 A의 광고 신고 5건 → 원시 5, 전체 고유 1, 호출 고유 1.
  같은 목록 재조회/새로고침/재시작/다중 탭에서도 유효 수가 늘지 않는다.
- **RPT-02 다른 계정:** A/B가 같은 대상을 광고 신고 → 전체 고유 2, 호출 고유 2.
  임계값 2이면 A의 반복만으로는 통과하지 못하고 B의 독립 신고가 있어야 통과한다.
- **RPT-03 이름 변경:** 계정 식별값이 같은 A가 이름을 바꾸고 신고 → 여전히 1명.
- **RPT-04 동명이인:** 표시 이름이 같아도 검증된 계정 식별값이 다른 A/B → 2명.
- **RPT-05 호출 신고 추가:** A의 일반 신고 후 광고 신고 → 전체 고유 1 유지, 호출 고유만 0→1.
  같은 A의 다른 글 신고는 별도 대상에 1회 기여한다.
- **RPT-06 필드 누락:** 대상 링크/신고자 이름/신고 내용 각각 누락·공백·읽기 실패 →
  유효 신고 확정 금지, 검토 사유 표시, 해당 미확인 집계로 자동 이동 금지.
- **RPT-07 계정 고유성 미확인:** 익명/이름만 제공/임시 ID만 있음 → 이름만으로 합치거나
  원시 건수만큼 다른 계정으로 부풀리지 않는다. 임의 reporterKey를 만들지 않고 미확인 처리.
- **RPT-08 필드 구분:** 내용에 `광고)`, `광고 의심`, `이미지 광고` → 키워드 일치.
  이름/제목/URL에만 `광고`, 내용은 일반 신고 → 호출 불일치.
  `광고가 아닌 것 같습니다` → 문자열 후보일 뿐 광고 점수/확정/자동 이동 근거가 아님.
- **RPT-09 링크 정규화:** 같은 실제 글의 허용된 추적 파라미터 차이 → 같은 대상.
  댓글 식별자가 다른 링크는 같은 부모 글이어도 별도 대상으로 유지하고 부모 글은 이동하지 않는다.
- **RPT-10 링크 오염:** 외부 호스트/유사 호스트/다른 채널/실행 URL/잘못된 대상/리다이렉트 불일치 → 제외.
  입력 링크 검증 전에 외부 내용을 수집하거나 임의 ID로 대상을 생성하지 않는다.
- **RPT-11 수집 범위:** 페이징 일부 누락/접근 제한/원시 총수만 제공 → 현재 고유 집계 미확인.
  마지막 검증 수와 현재 상태를 구분하고 미확인 자료로 자동 이동하지 않는다.
- **RPT-12 변경·철회:** 검증된 사이트가 신고 수정/철회를 제공하면 현재 집합에서 재계산.
  같은 자료 재수집이 가산되지 않고 지원하지 않는 철회 동작을 추측하지 않는다.
- **RPT-13 신뢰 경계:** 신고 내용에 다른 사람 이름/링크/개발 지시가 적혀 있어도
  실제 신고자/대상/명령으로 취급하지 않는다. 대상/계정은 사이트의 검증된 필드에서 읽는다.

### 기처리 및 복수 관리자 — Phase 7 Mock부터 검증

- **MOD-01 이미 TEST:** 최초 조회 시 대상이 검증된 TEST ID → 추가 분석/이동 불필요,
  `SKIPPED / ALREADY_HANDLED`. 자체 이동 성공 알림/카운터가 증가하지 않는다.
- **MOD-02 다른 처리 완료 탭:** 별도 검증된 처리 완료 글머리/이력이 있는 대상 → 추가 조치 없음.
  근거 없이 임의의 다른 탭을 처리 완료라고 간주하지 않는다.
- **MOD-03 분석 중 외부 이동:** 관리자 B가 A의 분석 중 글머리를 변경 → 이동 직전 조회에서
  확인하고 `SKIPPED / CATEGORY_CHANGED_EXTERNALLY`. TEST로 덮어쓰거나 원복하지 않는다.
- **MOD-04 사전 이력 미확인:** 최초 조회 이전의 이동 여부를 읽을 수 없고 대상이 임의의 다른 탭 →
  이미 처리됐다고 추정하지 않는다. 기존 판정/권한 조건과 검토 정책을 그대로 적용한다.
- **MOD-05 상태·권한 변경:** 본문 변경/삭제/권한 상실/조회 실패 → 안전한 검토/실패 처리.
  타 관리자 처리 완료나 자체 이동 성공으로 오기록하지 않는다.
- **MOD-06 읽기-쓰기 경합:** 최종 조회 뒤 B가 이동한 경우를 주입한다.
  검증된 조건부 쓰기가 있으면 충돌 시 중단한다. 없으면 잔여 경합을 문서화하고
  재조회만으로 정확히 한 번 처리를 보장한다는 테스트/표시를 만들지 않는다.
- **MOD-07 자동 실행 담당:** 담당 인스턴스 1개와 관찰 인스턴스 여러 개 → 관찰자는 쓰기하지 않는다.
  서로 다른 PC/계정에 로컬 잠금이 공유된다고 가정하지 않고, 동시 담당 실행은 안전성 미검증으로 취급한다.
- **MOD-08 불명확한 응답:** 시간 초과 직후 다른 관리자도 TEST로 이동 → 현재 상태를 확인하고
  추가 쓰기하지 않는다. 실행 주체가 불명확하면 자체 `MOVED_VERIFIED`로 확정하지 않는다.
- **MOD-09 기록 없음/로그 정리:** 캐시가 비었거나 최근 1,000건 밖으로 밀린 글이 TEST에 있음 →
  최신 상태로 기처리 판단하고 재이동하지 않는다. 로그 삭제로 신고 수가 다시 증가하지 않는다.
- **MOD-10 수동 복원:** 처리 이력은 있는데 관리자가 원래 탭으로 복원 → 상태 충돌 검토.
  명시적인 재검토 없이 옛 신고만으로 자동 재이동하지 않는다.
- **MOD-11 관리자별 집계:** 같은 신고를 보는 관리자 A/B의 ID를 중복 키에 넣지 않는다.
  각자의 관측 범위를 검증하고 계정/PC 수만큼 신고 기여가 늘어나지 않는다.

### 채널 설정과 정보 보관 — Phase 5/9

- **CFG-01 테스트 프로필:** `prlvate` → `TEST` 요구값을 채널별로 설정하되 감시/자동 이동은 OFF,
  권한은 unverified. `private`로 교정하거나 TEST ID를 추측하지 않는다.
- **CFG-02 대상 탭 확인:** TEST 이름 누락/복수 후보/권한 없음/다른 채널의 같은 이름 → 자동 조치 금지.
- **CFG-03 격리와 복원:** 테스트 채널 값이 다른 채널에 번지지 않고 가져오기/복원 시
  검증되지 않은 권한/자동 이동이 활성화되지 않는다.
- **CFG-04 보관 기한:** 이름/원문/계정 키를 기본 내보내기에 복사하지 않는다.
  기한 만료/손상 후 안전한 재구성이 불가능하면 미확인 상태로 중단하며 개인정보를 무기한 보관하지 않는다.
- **CFG-05 사용자 선택:** prlvate/TEST와 다른 합성 채널/탭을 UI에서 등록하고 변경한다.
  채널별로 서로 다른 대상을 사용할 수 있고 코드 수정이나 테스트 값 자동 등록을 요구하지 않는다.
- **CFG-06 작업 중 설정 변경:** 이동 대기 중 해당 채널/대상 변경 → 이전 작업 취소/재검토.
  낡은 설정으로 이동하거나 기처리 글을 새 대상으로 재이동하지 않는다. 다른 채널 작업은 영향 없음.
- **CFG-07 미설정/대상 소멸:** 최초 채널/대상 미설정 또는 선택한 탭이 사라짐 → 이동 불가.
  임의 기본 탭을 고르지 않고 사용자의 유효한 재선택과 권한 검증을 요구한다.

최초 실사이트 확인 장소는 `https://arca.live/b/prlvate`다. TEST의 실제 ID/권한을 검증하기 전에는
사이트 대상 쓰기 테스트를 실행하지 않는다. 이후에도 승인된 단일 테스트 글만 사용한다.

## 사용자 정의 주제·예외·이미지 링크 인수 계획 (미구현 / 미실행)

기준: `TOPIC_POLICIES.md`. 모든 주제/글/링크는 합성 입력이다. 실제 사이트 선택자나
주제별 동작을 검증했다는 의미가 아니다. 엔진 테스트는 Phase 2부터, 수집 연동은 승인된 Phase 1/4에서 진행한다.

- **TOP-01 주제 추가/격리:** 리딩방/쇼핑몰 링크와 비광고 거래글 주제를 생성·편집·비활성화·삭제.
  채널별 규칙/예외/대상이 섞이지 않고 거래글 결과를 광고 확정으로 표시하지 않는다.
- **TOP-02 이름만 등록:** 주제명만 있고 규칙 없음 → 초안/판별 불가. 자동 분류기나 이동 정책을 만들어내지 않는다.
- **TOP-03 예외 우선:** 탐지 규칙이 맞아도 해당 주제 자동 처리 제외 또는 검토 전환 예외가
  맞으면 높은 점수로 이를 무시하지 않는다. 규칙 단위 제외는 해당 근거에만 적용하고 사유를 표시한다.
- **TOP-04 예외 범위:** 한 주제의 허용 URL이 다른 주제까지 면제하지 않는다.
  명시적 채널 전체 자동 처리 차단 예외는 채널 범위를 따르며 다른 채널에는 번지지 않는다.
- **TOP-05 예외 오류:** 잘못된 정규식/시간 초과/필수 예외 입력 누락 → 예외 없음으로 통과시키지 않고 자동 조치 중단.
- **TOP-06 복수 주제:** 서로 다른 목적지면 관리자 검토, 같은 목적지면 단일 조치.
  주제 간 점수나 원시 신고 수를 합산해 임계값을 넘기거나 주제마다 글을 다시 이동하지 않는다.
- **TOP-07 정책 변경:** 분석 후 규칙/예외/주제/대상 변경·삭제·비활성화 → 이전 작업 취소/재검토.
  과거 처리 글을 새 주제 규칙에 따라 자동 재이동하지 않는다.
- **TOP-08 신고 호출:** 광고 호출어 `광고`와 비광고 호출어 `거래` 또는 채널 상속 값을 각각 확인.
  신고 내용은 탐지 근거가 아니고 같은 사용자의 원본 신고 기여가 주제 수만큼 늘어나지 않는다.

- **LNK-01 이미지 링크:** 본문에 표시 텍스트 URL 없이 이미지에만 href가 있음 →
  실제 목적지를 수집해 주제 URL 규칙에 입력. OCR/QR OFF 상태에서도 작동해야 한다.
- **LNK-02 정상 이미지:** 외부 CDN의 링크 없는 사진/일반 확대 링크 → 출처를 구별하고
  이미지/외부 링크 존재만으로 광고 확정/자동 이동하지 않는다.
- **LNK-03 주소 분리:** 이미지 src, 실제 href, OCR 속 주소, QR 주소가 모두 다름 →
  각 출처/연관 근거를 보존하고 src를 클릭 목적지로 오인하지 않는다.
- **LNK-04 구조와 범위:** 상대 href와 검증된 picture/지연 로딩 Mock을 해석하되
  사이드바/프로필 사진/사이트 배너를 게시물 내용 링크에 포함하지 않는다.
- **LNK-05 실행 금지:** javascript/data 등 실행 링크, 잘못된 URL, onclick만 있는 이미지 →
  실행/클릭/외부 방문 없이 미확인·unsupported로 구분. 링크 없음을 확정하지 않는다.
- **LNK-06 호스트 예외:** 허용 `shop.example`와 공격적 유사 호스트 `shop.example.evil.example` 구별.
  하위 도메인 허용 설정과 경로 예외 범위도 존중한다.
- **LNK-07 근거 중복:** 같은 목적지가 본문/이미지/OCR에 반복 → 동일 원천 근거를 독립 근거로 부풀리지 않음.
- **LNK-08 수집 오류/제한:** 필수 링크 자료 읽기 실패/수량·길이·시간 제한 초과 →
  링크 없음/정상 판정 대신 불완전 상태를 남기고 해당 자동 조치를 검토한다. 민감한 URL 쿼리를 로그에 복사하지 않는다.

## 백그라운드 처리·무방해 인수 계획 (미구현 / 미실행)

기준: `OPERATING_REQUIREMENTS.md` OP-07. 기본은 Mock 쓰기/합성 신고이며 실제 쓰기는
별도 승인된 단일 테스트 글에서만 검증한다. 테스트 도구가 관찰하는 것과 제품 코드의 화면 조작을 구별한다.

- **BKG-01 화면 보존:** 글/댓글 작성 및 읽기 중 Mock 이동/결과 재조회 완료 → URL/선택 탭/
  방문 기록/스크롤/activeElement/선택 범위/초안/IME 조합이 유지되고 새로고침/창 열기 없음.
- **BKG-02 UI 비의존:** 패널 닫힘·다른 글 열람·다른 브라우저 탭 선택 상태에서 조건 충족 →
  검증된 비동기 경로만 호출. 관리 버튼 클릭/새 탭/화면 전환 없이 결과를 재조회하고 기록한다.
  사이트의 정상 목록 갱신과 ArcaGuard가 강제한 재배치를 구분한다.
- **BKG-03 지원 불가:** 백그라운드 조치/결과 조회 미지원·권한 소실·로그인 필요·DOM 변경 →
  자동 처리 중단/검토 대기. 보이는 UI 조작이나 로그인 팝업으로 전환하지 않고 성공으로 기록하지 않는다.
- **BKG-04 조용한 안내:** 연속 성공/실패/기처리 건 → 기본 기록/고정 상태 표시만 갱신.
  패널 자동 열림/모달/토스트/소리/OS 알림/포커스 변경 없음. 개별 알림 opt-in도 중복/빈도 제한 적용.
- **BKG-05 부하와 입력:** 많은 신고/대형 본문/이미지 분석/느린 요청을 주입 → 입력·스크롤·긴급 중지
  응답을 성능 추적으로 확인. 무제한 동기 루프/병렬 쓰기/요청 폭주 없이 분할·한도·백오프가 적용된다.
  Phase별 대표 장치/최대 입력과 수치 예산을 먼저 기록하고 미충족 시 자동 처리량을 낮추거나 중단한다.
- **BKG-06 비활성·재개:** 비활성 탭 타이머 지연/페이지 정지 후 재개 → 최신 신고/설정/권한/
  기처리 상태를 재검증하고 제한된 큐로 재개. 지연 작업을 한꺼번에 보내거나 정시 실행을 주장하지 않는다.
- **BKG-07 종료 한계:** 실행 페이지/브라우저 종료·탭 폐기·절전 → 상시 감시/완료를 표시하지 않는다.
  재실행 시 최신 상태로 복원하고 누락 작업을 무조건 재이동하지 않는다.
- **BKG-08 중지·불명확 요청:** 대기 중 감시 OFF/긴급 중지 → 미전송 쓰기 취소.
  전송 중 중지/시간 초과 → 원복이나 미실행으로 단정하지 않고 결과 재조회 후 기록하며 무조건 재시도하지 않는다.
