# 검증 계획

## Phase 0

- `npm install`: 의존성 설치와 lockfile 생성.
- `npm run lint`: ESM/브라우저/Node 환경별 ESLint 검사.
- `npm run test`: UI 초기 닫힘, 중복 삽입 방지, 열기/닫기/Escape/포커스,
  안전 상태 표시 및 UI 확인 중 네트워크/저장소 호출 없음.
  승인된 위치 보완의 드래그/키보드/복원/초기화/경계/손상 자료/저장 차단도 포함한다.
  표시/고정 토글, 숨김 후 복원/단축키/포커스/IME, 손상 설정/저장 거부, 메뉴 Mock도 포함한다.
- `npm run build`: 설치 가능한 단일 `.user.js` 번들 생성 및 메타데이터/구문 검사.
- `npm run dev`: 루프백 개발 서버와 로컬 미리보기/개발 스크립트 응답 확인.
- 로컬 브라우저에서 화면 열기/확인/닫기와 좁은 화면 확인.
- Tampermonkey 설치와 실제 arca.live 렌더링은 별도 검증 대상으로 기록한다.

## Phase 1 로컬 브라우저 읽기 실험 (운영 기능과 별도)

- 재현: `node scripts/serve-read-lab.js` 실행 후 Chrome에서 `http://127.0.0.1:5184/`의 실험 버튼을 누른다.
  서버는 루프백 고정 합성 응답만 제공하며 도구/OS의 로컬 소켓 권한이 필요할 수 있다.
  개발 조사 전용이고 Userscript에서 import하지 않는다. 실험 후 서버를 종료한다.
- 응답 문자열/DOMParser/template.content의 3경로를 관측한다. 고정된 로컬 이미지/프레임/스타일/링크와
  스크립트·핸들러, 양성 대조 리소스로 관측 경로가 동작하는지 확인한다.
- 실제 Chrome에서 각 700ms 구간의 합성 추가 요청 0/스크립트 실행 0 및 화면 상태·초안 보존을 확인했다.
  JSON/화면은 `tests/manual/background-read-lab.chrome.*`, 범위와 한계는 SITE_VERIFICATION PLATFORM-03을 따른다.
- 기존 Vitest 33개와 구분되는 수동 브라우저 실험이다. 후속 인수 계획 78개 중 NTF-05 전체 통과나
  실제 사이트 파서/관리 쓰기 테스트로 집계하지 않는다. 모든 HTML/지연 요청/성능/IME/CSP/탭 정지를 보장하지 않는다.

  완료 OFF/ON, 중복 알림, 이미 이동됨, 이동 거절, 200 뒤 미변경, 신고 전송 실패, 신고 수 미달을 포함한다.
  UI 상태 보존과 서버의 요청 수/실제 변경 수/순서를 별도로 기록한다.
- ‘5초 후 실행’과 ‘입력 대조 탭 열기’로 추가 대조할 수 있다. 반드시 이벤트 당시의 실제 visibility/hasFocus를 확인한다.
  2026-10-25 실행은 대조 초안 보존을 확인했으나 **hidden 조건 미충족**이며 숨김 탭 통과로 집계하지 않는다.
- 최종 기준 실행 8/8, 별도 대조 실행 8/8. 결과는 `tests/manual/workflow-lab.chrome.*`, 세부는 PLATFORM-04다.
  이는 기존 Vitest 33개나 후속 인수 계획 78개의 운영 연동 테스트 통과 수에 합산하지 않는다.
  실제 사이트/Tampermonkey 실행/AI/IME/다중 관리자/정지된 탭의 성공을 입증하지 않는다.

## 후속 단계

Phase 1의 현재 근거는 공개 참고 소스와 사용자 제공 필드 정보다.
실제 DOM/권한을 보지 못한 선택자는 후보로만 남기고, 익명 JSON 전사 예시를 HTML 수집기 성공 증거로 사용하지 않는다.
`report-row.user-provided.json`의 작성자/신고자 분리, 사유 필드 존재/실제 값 미제공,
계정 키 미제공 및 합성 값 표시를 확인한다. 별도 고유 신고자 집계는 만들지 않으며 사이트 파서/감시는 미구현이다.

REQUIREMENTS.md 11장의 단위/통합/오탐 시나리오를 각 기능 추가 시 구현한다.
특히 잘못된 정규식, 시간 초과, 우회 문자열과 정상 인용/경고, 손상 설정,
권한 실패/신고 누락/댓글 신고/대상 없음/기처리/상태 변경/다중 탭을 포함한다.
OCR/AI 비활성 및 오류, 다중 채널 격리, 글머리 변경 실패와 검증을 포함한다.
모든 관리자 쓰기는 Mock으로 검사하며 최초 실사이트 테스트는 승인된 읽기만 허용한다.
글머리 변경은 추가 승인과 지정 테스트 글 하나로 제한한다.

### 신고 입력과 집계 — Phase 1 조사 후 Phase 4 구현

- **RPT-01 현재 값 재조회:** 사이트 총수 5를 세 번 읽음 → 현재 값은 5 유지, 15로 누적하지 않음.
  새로고침/재시작/다중 탭에서도 별도 신고자 집계 장부 없이 최신 값으로 교체한다.
- **RPT-02 사이트 수 변경:** 같은 대상의 표시 총수 1→2 → 최신 값 2 사용.
  임계값 2를 사이트 값으로 평가하며 계정별 기여를 로컬에서 다시 계산하지 않는다.
- **RPT-03 이름 변경:** 신고자 이름 표시가 바뀌어도 사이트 총수는 그대로 사용하며 새 신고로 더하지 않는다.
- **RPT-04 동명이인:** 표시 이름이 같아도 사이트 총수 2를 이름 중복이라는 이유로 1로 줄이지 않는다.
- **RPT-05 호출 사유 수:** 사이트 총수 5/현재 사유 중 키워드 일치 2 → 각각 별도 조건으로 사용.
  같은 사유 스냅샷을 다시 읽거나 복수 주제를 검사해도 누적 가산하지 않는다.
- **RPT-06 필드 누락:** 대상 링크/신고자 이름/신고 내용 각각 누락·공백·읽기 실패 →
  유효 신고 확정 금지, 검토 사유 표시, 해당 미확인 집계로 자동 이동 금지.
  준비 완료 후 노드 교체/채널 변경/필드 소멸 시 기존 스냅샷을 유효 상태로 재사용하지 않는다.
- **RPT-07 고유 키 불필요:** 필수 이름/대상/사유/사이트 총수가 정상이고 안정적 계정 키만 없음 →
  임의 reporterKey/신고자 장부를 만들지 않고 사이트 총수 사용. 계정 고유 키 부재만으로 차단하지 않음.
- **RPT-08 필드 구분:** 내용에 `광고)`, `광고 의심`, `이미지 광고` → 키워드 일치.
  이름/제목/URL에만 `광고`, 내용은 일반 신고 → 호출 불일치.
  작성자/신고자 표시가 같은 행도 각각 해당 필드로 읽으며 자기 신고라는 이유로 무효화하거나 광고 점수에 더하지 않는다.
  `광고가 아닌 것 같습니다` → 문자열 일치이나 광고 점수/분류 근거는 아님.
  OP-10 신고 기준 정책의 K 조건에는 포함되며 적용 가능한 예외/공통 검증은 별도로 평가함.
- **RPT-09 링크 정규화:** 같은 실제 글의 허용된 추적 파라미터 차이 → 같은 대상.
  댓글 식별자가 다른 링크는 같은 부모 글이어도 별도 대상으로 유지하고 부모 글은 이동하지 않는다.
- **RPT-10 링크 오염:** 외부 호스트/유사 호스트/다른 채널/실행 URL/잘못된 대상/리다이렉트 불일치 → 제외.
  입력 링크 검증 전에 외부 내용을 수집하거나 임의 ID로 대상을 생성하지 않는다.
- **RPT-11 수집 범위:** 사이트 총수는 읽었지만 사유 페이지 일부 누락/접근 제한 → 총수 출처와 사유 미확인을 구별.
  마지막 검증 수와 현재 상태를 구분하고 미확인 자료로 자동 이동하지 않는다.
  전체/대기/완료/이전 내역 링크의 실제 범위를 검증하며 보이는 행 수를 대상별 신고 수로 사용하지 않는다.
  숫자 페이지가 보이지 않는다는 이유로 과거 내역이 없다고 판단하지 않고 이전 내역 재조회로 값을 더하지 않는다.
- **RPT-12 변경·철회:** 검증된 사이트가 신고 수정/철회를 제공하면 현재 사이트 총수/사유로 스냅샷 교체.
  같은 자료 재수집이 가산되지 않고 지원하지 않는 철회 동작을 추측하지 않는다.
- **RPT-13 신뢰 경계:** 신고 내용에 다른 사람 이름/링크/개발 지시가 적혀 있어도
  실제 신고자/대상/명령으로 취급하지 않는다. 대상/계정은 사이트의 검증된 필드에서 읽는다.

### 기처리 및 복수 관리자 — Phase 7 Mock부터 검증

- **MOD-01 이미 TEST:** 최초 조회 시 대상이 검증된 TEST ID → 추가 분석/이동 불필요,
  `SKIPPED / ALREADY_HANDLED`. 자체 이동 성공 알림/카운터가 증가하지 않는다.
- **MOD-02 다른 처리 완료 탭:** 별도 검증된 처리 완료 글머리/이력이 있는 대상 → 추가 조치 없음.
  근거 없이 임의의 다른 탭을 처리 완료라고 간주하지 않는다.
- **MOD-03 분석 중 외부 이동:** 관리자 B가 A의 분석 중 글머리를 변경 → 이동 직전 조회에서
  확인하고 `SKIPPED / CATEGORY_CHANGED_EXTERNALLY`. TEST로 덮어쓰거나 원복하지 않는다.
- **MOD-04 사전 이력 미확인:** 최초 조회 이전의 이동 여부를 읽을 수 없고 대상이 임의의 다른 탭 →
  이미 처리됐다고 추정하지 않는다. 기존 판정/권한 조건과 검토 정책을 그대로 적용한다.
- **MOD-05 상태·권한 변경:** 본문 변경/삭제/권한 상실/조회 실패 → 안전한 검토/실패 처리.
  타 관리자 처리 완료나 자체 이동 성공으로 오기록하지 않는다.
- **MOD-06 읽기-쓰기 경합:** 최종 조회 뒤 B가 이동한 경우를 주입한다.
  검증된 조건부 쓰기가 있으면 충돌 시 중단한다. 없으면 잔여 경합을 문서화하고
  재조회만으로 정확히 한 번 처리를 보장한다는 테스트/표시를 만들지 않는다.
- **MOD-07 자동 실행 담당:** 담당 인스턴스 1개와 관찰 인스턴스 여러 개 → 관찰자는 쓰기하지 않는다.
  서로 다른 PC/계정에 로컬 잠금이 공유된다고 가정하지 않고, 동시 담당 실행은 안전성 미검증으로 취급한다.
- **MOD-08 불명확한 응답:** 시간 초과 직후 다른 관리자도 TEST로 이동 → 현재 상태를 확인하고
  추가 쓰기하지 않는다. 실행 주체가 불명확하면 자체 `MOVED_VERIFIED`로 확정하지 않는다.
- **MOD-09 기록 없음/로그 정리:** 캐시가 비었거나 최근 1,000건 밖으로 밀린 글이 TEST에 있음 →
  최신 상태로 기처리 판단하고 재이동하지 않는다. 로그 삭제로 신고 수가 다시 증가하지 않는다.
- **MOD-10 수동 복원:** 처리 이력은 있는데 관리자가 원래 탭으로 복원 → 상태 충돌 검토.
  명시적인 재검토 없이 옛 신고만으로 자동 재이동하지 않는다.
- **MOD-11 관리자별 조회:** 같은 신고를 보는 관리자 A/B의 사이트 총수는 합산하지 않는다.
  각자의 조회 범위를 확인하며 작업 중복 실행/기처리 확인은 유지한다.

  가져오기로 작성 페이지의 자동 새로고침/초안 손실이 발생하지 않는다.
- **CFG-04 보관 기한:** 이름/원문/계정 키를 기본 내보내기에 복사하지 않는다.
  기한 만료/손상 후 안전한 재구성이 불가능하면 미확인 상태로 중단하며 개인정보를 무기한 보관하지 않는다.
- **CFG-05 사용자 선택:** prlvate/TEST와 다른 합성 채널/탭을 UI에서 등록하고 변경한다.
  채널별로 서로 다른 대상을 사용할 수 있고 코드 수정이나 테스트 값 자동 등록을 요구하지 않는다.
- **CFG-06 작업 중 설정 변경:** 이동 대기 중 해당 채널/대상 변경 → 이전 작업 취소/재검토.
  낡은 설정으로 이동하거나 기처리 글을 새 대상으로 재이동하지 않는다. 다른 채널 작업은 영향 없음.
  현재 인스턴스의 중지는 지연 저장 전에 미전송 작업을 막고 다른 탭은 실행 직전 버전을 재확인한다.
  변경 메시지의 누락·지연을 주입하며 이를 다중 계정/PC의 잠금으로 판정하지 않는다.
- **CFG-07 미설정/대상 소멸:** 최초 채널/대상 미설정 또는 선택한 탭이 사라짐 → 이동 불가.
  임의 기본 탭을 고르지 않고 사용자의 유효한 재선택과 권한 검증을 요구한다.

최초 실사이트 확인 장소는 `https://arca.live/b/prlvate`다. TEST의 실제 ID/권한을 검증하기 전에는
사이트 대상 쓰기 테스트를 실행하지 않는다. 이후에도 승인된 단일 테스트 글만 사용한다.

## 사용자 정의 주제·예외·이미지 링크 인수 계획 (미구현 / 미실행)

기준: `TOPIC_POLICIES.md`. 모든 주제/글/링크는 합성 입력이다. 실제 사이트 선택자나
주제별 동작을 검증했다는 의미가 아니다. 엔진 테스트는 Phase 2부터, 수집 연동은 승인된 Phase 1/4에서 진행한다.

- **TOP-01 주제 추가/격리:** 리딩방/쇼핑몰 링크와 비광고 거래글 주제를 생성·편집·비활성화·삭제.
  채널별 규칙/예외/대상이 섞이지 않고 거래글 결과를 광고 확정으로 표시하지 않는다.
- **TOP-02 이름만 등록:** 주제명만 있고 규칙 없음 → 초안/판별 불가. 자동 분류기나 이동 정책을 만들어내지 않는다.
- **TOP-03 예외 우선:** 탐지 규칙이 맞아도 해당 주제 자동 처리 제외 또는 검토 전환 예외가
  맞으면 높은 점수로 이를 무시하지 않는다. 규칙 단위 제외는 해당 근거에만 적용하고 사유를 표시한다.
- **TOP-04 예외 범위:** 한 주제의 허용 URL이 다른 주제까지 면제하지 않는다.
  명시적 채널 전체 자동 처리 차단 예외는 채널 범위를 따르며 다른 채널에는 번지지 않는다.
- **TOP-05 예외 오류:** 잘못된 정규식/시간 초과/필수 예외 입력 누락 → 예외 없음으로 통과시키지 않고 자동 조치 중단.
- **TOP-06 복수 주제:** 서로 다른 목적지면 관리자 검토, 같은 목적지면 단일 조치.
  주제 간 점수나 원시 신고 수를 합산해 임계값을 넘기거나 주제마다 글을 다시 이동하지 않는다.
- **TOP-07 정책 변경:** 분석 후 규칙/예외/주제/대상 변경·삭제·비활성화 → 이전 작업 취소/재검토.
  과거 처리 글을 새 주제 규칙에 따라 자동 재이동하지 않는다.
- **TOP-08 신고 호출:** 광고 호출어 `광고`와 비광고 호출어 `거래` 또는 채널 상속 값을 각각 확인.
  신고 내용은 탐지 근거가 아니고 주제별 수를 합산해 사이트 총수를 부풀리지 않는다.
- **TOP-09 후기형 홍보 양성·대조:** 사용자 확인 광고의 구조를 합성한 투자 손실 경험/특정 인물 추천/
  안내 칭찬/참여 권유 사례를 양성으로 포함한다. 화면에 URL/노골적 광고어가 없다는 이유만으로 제외하지 않는다.
  작성글 0~4개는 보조 신호로만 평가하고 조회 불가/일부 범위를 0개로 바꾸지 않는다.
  최근 활동 목록/15개 표시 한도/구분 요소 누락을 전체 글 수나 신규 가입의 근거로 사용하지 않는다.
  정상 투자 후기/단순 감사/피해 경고 및 동일 문구 인용을 대조하여 단순 키워드/유사도에 의한 자동 이동을 금지한다.
  이미 삭제된 원사례는 추가 조치/복원/자체 이동 성공 집계가 없고, 일반 조회 실패는 삭제로 확정하지 않는다.

- **LNK-01 이미지 링크:** 본문에 표시 텍스트 URL 없이 이미지에만 href가 있음 →
  실제 목적지를 수집해 주제 URL 규칙에 입력. OCR/QR OFF 상태에서도 작동해야 한다.
- **LNK-02 정상 이미지:** 외부 CDN의 링크 없는 사진/일반 확대 링크 → 출처를 구별하고
  이미지/외부 링크 존재만으로 광고 확정/자동 이동하지 않는다.
- **LNK-03 주소 분리:** 이미지 src, 실제 href, OCR 속 주소, QR 주소가 모두 다름 →
  각 출처/연관 근거를 보존하고 src를 클릭 목적지로 오인하지 않는다.
- **LNK-04 구조와 범위:** 상대 href와 검증된 picture/지연 로딩 Mock을 해석하되
  사이드바/프로필 사진/사이트 배너를 게시물 내용 링크에 포함하지 않는다.
- **LNK-05 실행 금지:** javascript/data 등 실행 링크, 잘못된 URL, onclick만 있는 이미지 →
  실행/클릭/외부 방문 없이 미확인·unsupported로 구분. 링크 없음을 확정하지 않는다.
- **LNK-06 호스트 예외:** 허용 `shop.example`와 공격적 유사 호스트 `shop.example.evil.example` 구별.
  하위 도메인 허용 설정과 경로 예외 범위도 존중한다.
- **LNK-07 근거 중복:** 같은 목적지가 본문/이미지/OCR에 반복 → 동일 원천 근거를 독립 근거로 부풀리지 않음.
- **LNK-08 수집 오류/제한:** 필수 링크 자료 읽기 실패/수량·길이·시간 제한 초과 →
  링크 없음/정상 판정 대신 불완전 상태를 남기고 해당 자동 조치를 검토한다. 민감한 URL 쿼리를 로그에 복사하지 않는다.

## 백그라운드 처리·무방해 인수 계획 (미구현 / 미실행)

기준: `OPERATING_REQUIREMENTS.md` OP-07. 기본은 Mock 쓰기/합성 신고이며 실제 쓰기는
별도 승인된 단일 테스트 글에서만 검증한다. 테스트 도구가 관찰하는 것과 제품 코드의 화면 조작을 구별한다.

- **BKG-01 화면 보존:** 글/댓글 작성 및 읽기 중 Mock 이동/결과 재조회 완료 → URL/선택 탭/
  방문 기록/스크롤/activeElement/선택 범위/초안/IME 조합이 유지되고 새로고침/창 열기 없음.
- **BKG-02 UI 비의존:** 패널 닫힘·다른 글 열람·다른 브라우저 탭 선택 상태에서 조건 충족 →

- **BKG-03 지원 불가:** 백그라운드 조치/결과 조회 미지원·권한 소실·로그인 필요·DOM 변경 →

- **BKG-04 조용한 안내:** 연속 성공/실패/기처리 건 → 기본 기록/고정 상태 표시만 갱신.
  패널 자동 열림/모달/토스트/소리/OS 알림/포커스 변경 없음. 개별 알림 opt-in도 중복/빈도 제한 적용.
- **BKG-05 부하와 입력:** 많은 신고/대형 본문/이미지 분석/느린 요청을 주입 → 입력·스크롤·긴급 중지
  응답을 성능 추적으로 확인. 무제한 동기 루프/병렬 쓰기/요청 폭주 없이 분할·한도·백오프가 적용된다.
  조회 시간보다 주기가 짧거나 추가 알림이 연속 도착해도 같은 채널의 동일 조회 주기가 중첩되지 않는다.
  Phase별 대표 장치/최대 입력과 수치 예산을 먼저 기록하고 미충족 시 자동 처리량을 낮추거나 중단한다.
- **BKG-06 비활성·재개:** 비활성 탭 타이머 지연/페이지 정지 후 재개 → 최신 신고/설정/권한/
  기처리 상태를 재검증하고 제한된 큐로 재개. 지연 작업을 한꺼번에 보내거나 정시 실행을 주장하지 않는다.
  화면 목록 갱신의 중지와 배경 읽기 허용을 구별하며 숨김만으로 항상 실행 불가라고 판정하지 않는다.
- **BKG-07 종료 한계:** 실행 페이지/브라우저 종료·탭 폐기·절전 → 상시 감시/완료를 표시하지 않는다.
  재실행 시 최신 상태로 복원하고 누락 작업을 무조건 재이동하지 않는다.
- **BKG-08 중지·불명확 요청:** 대기 중 감시 OFF/긴급 중지 → 미전송 쓰기 취소.
  전송 중 중지/시간 초과 → 원복이나 미실행으로 단정하지 않고 결과 재조회 후 기록하며 무조건 재시도하지 않는다.

## 사이트 신고 알림 연동 인수 계획 (미구현 / 미실행)

기준: OP-09, 사용자 제공 알림/상세 구조. 실제 이름/신고 ID/원문 대신 합성 자료와 Mock을 사용한다.

- **NTF-01 알림 후보:** 유효한 같은 채널 신고 상세 링크 알림 → 배경 읽기 후보 큐.
  메시지/종 모양 표시/알림 수만으로 광고 확정/이동/사이트 신고 수 증가 없음. 유형/채널/링크 미확인은 제외/검토.
- **NTF-02 상세 결합:** 유형 ARTICLE/대상/작성자와 신고자별 사유를 구별한다.
  사유에 `광고` 포함 시 호출 후보이며 본문 광고 근거로 가산하지 않는다. 사이트 현재 총수 1을 읽고 재조회 시 가산하지 않는다.
- **NTF-03 반복·기처리:** 동일 알림 재전달/재연결/다중 탭 → 신고 이벤트 중복 억제.
  별도 신고자 집계 없이 사이트 현재 수로 교체한다. 다른 관리자 처리/삭제 후 과거 알림은 추가 이동/복원 없음.
- **NTF-04 알림 없음:** 사이트 알림 OFF/닫힌 패널에 DOM 없음/과거 알림 누락 → 알림 없음과 신고 없음 구별.
  검증된 목록 대조/백오프를 사용하되 알림 패널 강제 열기/사이트 설정 변경/요청 폭주 없음.
- **NTF-05 화면·읽음 보존:** 알림 후보부터 상세 읽기까지 URL/선택 탭/포커스/스크롤/작성 내용 보존.
  자동 클릭/모두 읽기/읽음 표시 조작 없음. 읽기 단계에 신고 상태 쓰기를 끼워 넣지 않음.
  별도 OP-11 제출은 ACK 계획에서 검증하며 상세 읽기의 부작용 미확인 시 해당 읽기 경로 보류.
  합성 응답의 img/iframe/외부 목적지/스크립트로 파싱 중 추가 요청·실행이 없는지 브라우저 네트워크 관측으로 검증한다.
  분리된 문서라는 이유만으로 통과시키지 않으며 jsdom만의 결과를 실제 Chrome 무요청 증거로 사용하지 않는다.
  CSP/Trusted Types로 파싱이 막히면 보류하고 활성 DOM/숨겨진 프레임/정책 완화로 대체하지 않는다.
- **NTF-06 권한·유형·실패:** 접근 거부/로그인 필요/상세 사유 누락/알림과 대상 불일치/미지원 유형 → 자동 처리 차단.
  현재 페이지로 로그인/상세 창을 띄우지 않고 재시도 폭주 없이 검토 상태 기록. 댓글을 부모 글로 이동하지 않음.

## 선택형 조치 정책 인수 계획 (미구현 / 미실행)

기준: OP-10. 아래 MODE-01~08은 후속 Phase의 Mock 테스트 계획이며 현재 Vitest 통과 수에 포함되지 않는다.

- **MODE-01 신고 기준 경계:** A, N=3/K=1에서 사이트 총수 2/호출 1, 총수 3/호출 0은 이동 불가.
  총수 3/호출 1이면 AI/OCR/본문 점수 없이 자격 충족. K=2일 때 호출 1은 불충족.
  광고 확정으로 기록하지 않으며 A에서 분류 점수 임계값/AI 설치를 몰래 요구하지 않는다.
- **MODE-02 AI 조건 경계:** B, N=3에서 총수 2/AI 광고는 이동 불가, 총수 3/AI 광고는 자격 충족.
  사유에 호출어가 없어도 유효한 신고라면 통과 가능. 비광고는 이동 없음이며 키워드/규칙 양성으로 대체하지 않는다.
- **MODE-03 AI 불가:** OFF/모델 미준비/미지원 주제/시간 초과/낮은 신뢰도/잘못된 출력/입력 누락 → 검토 대기.
  광고 양성/A 정책으로 자동 전환하지 않는다. 신고 사유의 광고 표현을 AI 본문 입력/양성 근거로 넣지 않는다.
- **MODE-04 공통 차단:** A/B 모두 권한 소실/예외 일치·오류/검증된 글 이동 완료/외부 이동/대상 미검증/댓글 신고/
  목적지 충돌/배경 요청 미지원/긴급 중지에서 쓰기 없음. A는 예외 검사에 필요한 자료를 생략하지 않는다.
  Simulation/관리자 검토에서는 조건을 충족해도 Mock 쓰기를 호출하지 않는다.
- **MODE-05 정책 변경:** A→B/B→A/N/K/호출어/예외/모델 기준 변경 → 미전송 작업 취소/재평가.
  이전 AI 결과/정책으로 이동하지 않으며 이미 전송된 쓰기는 결과 확인. 한 글의 작업/성공을 중복 증가시키지 않는다.
- **MODE-06 설정 검증·격리:** 알 수 없는 정책/N·K의 0·음수·소수·NaN·안전 정수 초과/손상 상속 → 자동 실행 차단.
  마이그레이션/가져오기/최초 설정은 자동 이동 OFF/Simulation이며 모드 선택으로 감시가 켜지지 않는다.
  채널/주제별 선택·상속이 다른 채널에 번지지 않고 상속 변경 시 영향받는 대기 작업도 무효화한다.
- **MODE-07 최신 값·AI 지문:** 이동 직전 사이트 수가 N 아래로 감소/A의 호출 수가 K 아래로 감소하면 중단.
  B의 글 내용/모델·정책 버전이 바뀌면 기존 AI 양성 결과로 이동하지 않는다. 재조회는 덧셈 없이 최신 값으로 교체한다.
- **MODE-08 의미 구별:** 알림만/이름·제목에만 호출어가 있으면 A 조건으로 세지 않는다.
  `광고가 아님` 사유도 문자열 포함 수에는 들어감을 설정·미리보기로 표시하고 예외와 함께 평가한다.
  A 기록은 신고 조건 충족, B 기록은 유효한 AI 광고 판정으로 구별하며 어느 것도 이동 후 재조회 전 성공이 아니다.

## 신고 처리 카테고리·답변 인수 계획 (미구현 / 미실행)

기준: OP-11. ACK-01~08은 후속 Phase의 Mock 계획이며 실제 사이트 전송/단위 테스트 통과 수와 구분한다.

- **ACK-01 분류·이름 변경:** 채널별 사용자 지정 신고 분류/처리 버튼과 이동 대상 글머리를 따로 선택.
  동명/버튼 이름 변경·삭제·재생성·효과 변경/불명확 ID → 재확인/보류. `광고`/첫 버튼/색으로 자동 대체하지 않는다.
  별도 신고 카테고리 필드가 없는 사이트에 가짜 필드나 카테고리 생성 요청을 만들지 않는다.
- **ACK-02 효과 차단:** 선택한 버튼의 삭제/차단 효과 있음·미확인·미리보기 공란/누락·권한 변경 → 자동 제출 없음.
  공란은 무해함의 증거가 아니다. 안전한 효과/권한/배경 제출·결과 읽기를 독립 검증한 경우만 제출 자격이 있다.
- **ACK-03 상태 분리:** 신고 완료이나 글 이동 미확인 → 이동 성공으로 기록하지 않고 검토.
  기본 자동 흐름은 글 이동 검증 후 별도 활성화된 신고 제출. 신고 제출 OFF이면 글 이동이 완료돼도 제출 없음.
- **ACK-04 부분 실패:** 글 이동 성공/신고 제출 실패·시간 초과 → 부분 완료, 글 재이동 없음.
  현재 신고 상태/처리자/답변을 먼저 재조회하고 모호한 응답으로 무조건 재전송하지 않는다.
  신고만 완료된 수동 사례도 전체 처리 성공으로 주장하지 않는다.
- **ACK-05 타 관리자·다중 신고:** 다른 관리자 완료/답변 변경은 재전송·덮어쓰기 없음.
  같은 글의 여러 신고 코드는 글 이동을 중복시키지 않으며 신고별로 현재 상태/권한을 확인한다.
- **ACK-06 문구 검증:** 선택한 카테고리·버튼의 실제 지정 문구를 미리보기와 대조하고 변경/미확인 시 보류.
  자유 답변 필드/변수 치환/사이트 프리셋 자동 수정 요청을 만들지 않는다. HTML/코드는 표시만 하며 실행하지 않는다.
  신고자 원문/인증 정보 자동 삽입 없음, 이동 미확정/Simulation에서 격리 완료 답변을 전송하지 않는다.
- **ACK-07 작성자 통지·화면 보존:** 통지 기본 OFF, 명시적 선택 없는 작성자 알림 없음.
  Simulation/검토/긴급 중지에서 전송 없음. 실제 버튼/전송 자동 클릭·새 탭·포커스/스크롤/초안 변경 없음.
  관리자용 결과 알림과 작성자 통지의 수신 대상/효과를 구별한다.
- **ACK-08 설정 변경·상속:** 채널/주제별 신고 분류/버튼/문구/통지 변경·상속 갱신 → 미전송 작업 재평가.
  가져오기/복구로 신고 제출/작성자 통지 활성화 금지. 다른 채널 설정에 영향 없음.
