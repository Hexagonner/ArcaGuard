## OP-01. 사용자가 선택하는 채널과 대상

- 사용자는 설정 화면에서 사용할 채널을 직접 추가/변경/삭제하고, 각 채널의 이동 대상 탭을
  독립적으로 선택/변경할 수 있어야 한다. 특정 채널/탭 전용 프로그램으로 제한하지 않는다.
- 최초 실행의 등록 채널과 이동 대상은 미설정이다. 예시/테스트 설정을 자동 등록하지 않는다.
- 선택할 수 있는 범위는 실제 존재하고 현재 관리자에게 필요한 권한이 있는 채널/글머리다.
  채널에서 조회한 실제 글머리 목록을 표시해 선택하며 내부 ID나 코드를 사용자가 직접 수정할 필요가 없어야 한다.
- 채널마다 대상 이름과 검증된 글머리 ID를 보관하고 같은 이름의 다른 채널 글머리와 혼동하지 않는다.
- 설정 변경 시 해당 채널의 대기 작업은 이전 설정으로 이동하면 안 된다. 작업의 채널/대상/
  설정 버전을 이동 직전에 재확인하고 변경된 작업은 취소 또는 재검토한다. 새 대상을 임의로 적용해 재이동하지 않는다.
- 대상이 사라졌거나 권한/목록을 확인하지 못하면 이동을 중단하고 다시 선택하도록 안내한다.
  채널/대상이 미설정이면 자동 이동할 수 없다. 다른 채널의 설정에는 영향을 주지 않는다.

### 개발 테스트용 선택 예시 (고정값/기본값 아님)

- 테스트 채널: **https://arca.live/b/prlvate**. 채널 표기는 `prlvate`이며 `private`가 아니다.
- 해당 채널에서 광고 판정 기준을 충족한 미처리 글의 이동 대상 이름: **TEST**.
- 사용자가 해당 채널의 관리자임을 밝혔다. 상태는 `user-provided`이며 사이트 권한 검증은 `unverified`다.
- TEST의 실제 글머리 ID/존재/선택 가능 여부/이동 의미는 미검증이다. 조회한 목록에서
  정확한 채널/대상을 확인해야 한다. 이름이 없거나 복수 후보이면 임의 선택하지 않는다.
- 이 값은 테스트용 채널 설정으로 사용할 요구사항이며 현재 실행 설정을 생성한 것은 아니다.
  다른 채널의 설정/기본 대상/관리 권한에 영향을 주지 않는다.
- 지정 채널이라는 이유로 채널 전체의 글을 시험 이동하지 않는다. 최초 쓰기 테스트에는
  단계 승인, 실제 UI/권한 확인, 사용자가 지정한 단일 테스트 글과 쓰기 승인이 필요하다.

## OP-02. 신고 입력 검증

개별 신고에서 다음 정보를 사이트가 제공한 필드로 읽고 검증 결과를 분리한다.

- `targetUrl`: 신고된 글/댓글의 실제 링크. 신고 내용에 임의로 적힌 링크를 대상이라고 믿지 않는다.
- `channelId`, `targetType`, `articleId`, 필요한 경우 `commentId`: 검증된 대상 식별 정보.
- `reporterDisplayName`: 사이트가 표시한 신고자 이름. 공백/누락 여부를 검사하고 화면에서 확인 가능해야 한다.
- `reporterKey`: 같은 사용자를 안정적으로 구별할 수 있는, 출처/의미가 검증된 사이트 계정 식별값.
- `reasonText`: 실제 신고 내용. 누락/읽기 실패와 정상적으로 읽은 내용을 구별한다.
- `keywordMatched`: 신고 내용에 기본 키워드 **광고**가 포함되는지 여부.
- 비광고 주제에는 사용자가 설정한 주제별 신고 호출 조건을 평가한다. 광고는 기본값이며 고정된 유일 주제가 아니다.
- 사이트가 제공하는 경우 `reportId`, 신고 시각, 철회/유효 상태, 조회 범위/완전성.
- 필수 정보별 `verified`, `missing`, `unsupported`, `error` 등 검증 상태와 근거.

대상 링크 검증은 사이트 어댑터에서 확인한 URL 구조에 한해 구현한다. HTTPS arca.live와
등록한 채널/실제 대상 ID를 확인하고 외부 호스트/다른 채널/실행 가능한 URL은 제외한다.
추적 파라미터가 달라도 같은 실제 대상이면 같은 키로 처리하되 댓글 식별자는 보존한다.
단순히 모든 쿼리/fragment를 지우거나 URL 형태를 추측해 댓글을 부모 글로 바꾸지 않는다.
서버 리다이렉트 등으로 대상이 달라지면 최종 대상도 확인한다.

이름과 계정 식별값은 신고자가 신고 내용에 적어 넣은 문자열이 아니라 사이트 필드에서 얻는다.
닉네임만으로 동일 계정임을 단정하지 않는다. 사이트가 닉네임을 고유·불변 식별자로
보장하는지 검증하지 못했다면 이름만 제공되는 신고는 고유 사용자 수에 포함하지 않는다.
익명/비회원/식별값 미제공 사례에 임의의 계정 ID를 부여하지 않는다.

이름/대상 링크/신고 내용이 누락되거나 신고자 고유성을 검증할 수 없으면 검토 대상으로 표시하고,
이를 유효 신고로 계산하거나 `REPORT_VERIFIED`로 진행시키지 않는다.
일부 목록/페이지를 읽지 못해 현재 대상의 집계를 확인할 수 없으면 집계 상태는 `unverified`다.
숫자로 표시된 사이트 신고 건수만으로 고유 신고자 수를 채우지 않는다.

## OP-03. 신고자별 카운터와 키워드

대상 키는 채널 + 유형 + 실제 글 ID + 댓글 ID(게시글이면 없음)로 구분한다.
중복 기여 키는 **대상 키 + reporterKey**다. 관리자의 계정/브라우저/PC는 이 키에 넣지 않는다.

- `rawReportCount`: 확인 가능한 원시 신고 행 수. 참고 표시용이며 이동 임계값에 직접 쓰지 않는다.
- `uniqueReporterCount`: 검증된 유효 신고를 낸 서로 다른 사용자 수.
- `uniqueKeywordReporterCount`: 그중 키워드 포함 유효 신고를 한 번 이상 낸 서로 다른 사용자 수.
- 집계는 원본 자료의 검증 상태/완전성과 함께 보관한다. 두 고유 카운터의 기본 임계값은 각각 1명.

같은 사용자 A가 한 글을 5회 신고해도 전체 고유 수는 1이다. 그중 광고 신고가 3회여도
호출 고유 수는 1이다. A가 일반 신고 후 광고 신고를 추가하면 전체는 1을 유지하고 호출만 0→1이다.
다른 사용자 B가 광고 신고를 더해야 두 수가 각각 2가 된다.
같은 A가 다른 글을 신고하면 그 대상에는 별도로 1을 기여한다.
다른 이름의 동일 계정은 1명, 같은 이름의 다른 검증된 계정은 2명이다.

새로고침/재수집/재시작/페이지 이동/다중 탭이 같은 신고를 새 기여로 만들면 안 된다.
검증된 현재 신고 집합으로 다시 계산하거나 이에 준하는 멱등 병합을 사용한다.
철회/수정이 사이트에 제공될 때만 그 의미를 검증해 반영하고, 반복 신고로 누적 점수를 올리지 않는다.
수집 범위나 상태가 불명확하면 마지막 검증 집계와 현재 미확인 상태를 구별하고 자동 이동을 중단한다.

기본 일치는 신고 내용을 문자열로 확인한 뒤 `광고` 포함 여부를 검사한다.
`광고)`, `광고 의심`, `사진에 광고가 있습니다`는 일치한다.
제목/링크/신고자 이름에만 `광고`가 있으면 불일치다.
`광고가 아닌 것 같습니다`도 문자열 후보가 되지만 게시글 광고 근거에는 포함하지 않는다.
사용자 설정으로 키워드를 바꿀 수 있으며 복잡한 정규식은 기존 안전 요구사항을 따른다.
주제별 호출 조건을 사용해도 원본 신고의 사용자/대상 중복 기여는 1회이며 주제 수만큼 합산하지 않는다.

중복 방지는 **ArcaGuard 내부 집계**에 적용한다. 사이트의 신고 기능을 수정하거나
사이트가 접수하는 반복 신고 자체를 막는 기능은 아니다.

## OP-04. 복수 관리자와 이미 처리된 글

관리자는 여러 명일 수 있다. 각 계정의 해당 채널 읽기/이동 권한은 개별 검증한다.
어느 관리자/PC가 처리했든 확인된 기처리 대상에 추가 이동/재시도/성공 알림을 발생시키지 않는다.

향후 처리 순서는 다음과 같다.

1. 신고 입력/고유 집계가 유효한지 확인한다.
2. 대상의 최신 글머리/존재/상태를 읽는다. 이미 해당 채널에 설정한 이동 대상 또는 검증된 처리 완료 글머리이면 건너뛴다.
3. 미처리 대상만 분석한다. 분석 당시 글머리 ID와 검증 가능한 상태 지문을 기록한다.
4. 이동 직전에 로그인/권한/최신 글머리/선택된 채널·대상/설정 버전/긴급 중지를 다시 확인한다.
5. 다른 관리자가 이동한 것으로 확인되면 덮어쓰지 않고 건너뛴다.
6. 상태가 그대로이고 주제별 탐지/예외/신고/권한/모드/정책 충돌 조건을 모두 만족할 때만 승인된 조치를 한다.
7. 조치 후 현재 상태를 읽어 확인한다. 실패/시간 초과/불명확 응답이면 쓰기 재시도부터 하지 않는다.

- `SKIPPED / ALREADY_HANDLED`: 최초 조회/이동 직전 이미 설정된 이동 대상 또는 확인된 처리 완료 글머리.
- `SKIPPED / CATEGORY_CHANGED_EXTERNALLY`: 분석 후 다른 관리자에 의한 이동이 확인됨.
- 단순 내용 변경/삭제/권한 상실/조회 실패는 기처리 성공으로 취급하지 않고 검토/실패로 남긴다.
- `MOVED_VERIFIED`는 우리가 실행한 이동과 결과를 확인한 경우에만 사용한다.
  애매한 요청 후 설정된 대상 탭에 있어도 실제 실행 주체가 불명확하면 자체 성공으로 단정하지 않는다.
- 다른 관리자가 이미 이동한 사실을 확인했으면 원복하거나 현재 설정한 대상으로 강제 이동하지 않는다.
  최초 조회 이전의 이력은 검증된 이력이 있을 때만 사용한다. 임의의 다른 탭은 처리 완료 표시가 아니다.
- 사용자가 나중에 글을 원래 탭으로 되돌려도 과거 처리 건을 자동 재이동하지 않는다.
  기록과 현재 상태가 충돌하면 관리자 검토로 보내고 명시적인 재검토 없이는 다시 조치하지 않는다.
- 이동 대상 설정을 바꿔도 과거 기처리 이력이 사라지지 않는다. 예전 대상에 있던 처리 글을
  새 대상에 없다는 이유만으로 미처리로 바꾸거나 자동 재이동하지 않는다.

여러 PC의 로컬 저장소/GM 값은 공유 잠금이 아니다. 재조회와 쓰기 사이에 다른 관리자가
조치할 수 있으므로 이 설계만으로 중복 요청을 절대 0회로 만들거나 정확히 한 번 실행을 보장하지 않는다.
사이트가 검증된 원자적/조건부 변경 기능을 제공하면 그 범위에서 활용할 수 있으나 API를 추측하지 않는다.
없는 경우 **채널별 자동 실행 인스턴스 1개 + 나머지 관찰/수동 검토**를 운영 대안으로 설계한다.
이 역시 원격 관리자/수동 조치에 대한 완전한 잠금이 아니며 안전성 검증 전 자동 이동은 계속 OFF다.

## OP-05. 정보 보관과 채널 격리

- 신고자 이름/내용은 검증과 관리자 검토에 필요한 범위에서만 접근한다.
- 신고자 구분 키는 채널/대상 범위를 벗어난 사용자 추적 용도로 사용하지 않는다.
- 인증 토큰/쿠키/비밀번호를 reporterKey로 사용하거나 저장하지 않는다.
- 기본 로그/내보내기에는 신고 원문/이름/계정 식별값을 자동 복사하지 않는다. 필요 시 합계와
  판정 사유를 사용한다. 개인정보 제거를 위한 해시를 익명화 보장으로 설명하지 않는다.
- 집계/중복 방지 상태와 최근 1,000건 처리 로그의 수명은 구별한다. 로그 정리만으로
  기처리 글이 새 대상으로 되거나 중복 신고가 다시 더해지면 안 된다.
- 보관 기한 만료/상태 손상 시 새로 검증된 현재 신고 집합과 사이트 상태를 읽어야 하며,
  재구성할 수 없으면 자동 처리를 중단한다. 오래된 개인정보를 무기한 보관하는 방식은 쓰지 않는다.
- 테스트에는 가짜 계정 A/B와 합성 신고 내용을 사용한다. 실제 비공개 신고/신고자 이름을
  Fixture/스크린샷/문서/외부 서비스로 복사하지 않는다.

## OP-06. 구현 단계와 검증 책임

- Phase 1: 지정 채널의 허용된 읽기 조사에서 URL/신고 필드/계정 식별 가능 여부/
  글머리 목록/상태/이력 제공 여부를 확인한다. 사용자 제공 정보와 실측 근거를 분리한다.
- Phase 4: 신고 필드 검증, 고유 집계, 재수집 멱등성, 댓글 구분 및 정보 누락 시 중단을 구현한다.
- Phase 5: 사용자의 채널 추가/변경/삭제와 채널별 대상 탭 선택/변경,
  원시 수와 고유 수/검증 상태/기처리 사유와 관찰 모드를 표시한다.
- Phase 7: 승인된 단일 글에서 최신 상태 재조회, 외부 이동 건너뛰기, 결과 검증과 경합 한계를 검사한다.
- Phase 9: 복수 계정/탭/PC, 로그 정리/재시작/설정 복원 후 중복 처리 회귀를 검증한다.

인수 시나리오는 [TEST_PLAN.md](TEST_PLAN.md)의 `RPT-*`, `MOD-*`, `CFG-*`를 따른다.
현재 위 계약에 대한 동작 테스트/실사이트 확인은 수행하지 않았다. 구현한 것처럼 보고하지 않는다.

## OP-07. 백그라운드 처리와 사용 방해 금지

광고 글의 이동은 서버의 글머리/분류를 바꾸는 조치이며 브라우저 탭을 이동하는 기능이 아니다.
관리자가 글을 읽거나 작성하거나 다른 브라우저 탭을 사용하는 동안에도,
실행 가능한 Userscript 인스턴스가 검증된 백그라운드 요청으로 처리해야 한다.
감시와 자동 이동은 여전히 기본 OFF이며 기존 신고/주제/권한/기처리/상태 검증 조건을 모두 적용한다.

- 자동 처리로 현재 URL/브라우저 선택 탭/방문 기록을 변경하거나 페이지를 새로고침하지 않는다.
  새 탭/창/팝업/보이는 관리 화면을 열거나 자동으로 닫지 않는다. 숨겨진 탭을 여는 방식도 사용하지 않는다.
- 스크롤, 포커스, 커서/선택 범위, 입력 중인 글/댓글/검색어/IME 조합을 건드리지 않는다.
  현재 읽는 글을 강제로 제거하거나 목록을 재배치하지 않는다. 결과는 기록에 반영하고
  사이트 자체의 정상 갱신 외에 현재 화면 갱신을 강제하지 않는다.
- 자동 조치나 결과 검증을 위해 실제 화면의 관리 메뉴/드롭다운/이동 버튼을 대신 누르지 않는다.
  관리자 UI에서 관찰·검증한 허용된 요청 방식과 필요한 권한을 확인한 뒤 별도 어댑터로 실행한다.
  미확인 API 추측이나 인증 자료 저장으로 이를 대체하지 않는다.
- 백그라운드 요청 및 결과 재조회가 불가능하거나 재로그인/사용자 확인이 필요하면
  해당 자동 처리를 중단하고 검토 대기로 남긴다. 화면 조작으로 전환하거나 로그인 창을 강제하지 않는다.
  관리자에게 직접 이동을 제안할 수는 있지만 수동 작업과 자동 처리 성공을 구별한다.
- 기본 성공 안내는 처리 기록과 배치가 바뀌지 않는 조용한 상태 표시다. 작업마다 패널을 열거나
  포커스를 가져오거나 모달/토스트/OS 알림/소리를 발생시키지 않는다. 선택적 개별 알림도
  명시적 사용자 설정과 중복 억제/빈도 제한을 적용하며 화면이나 포커스를 바꾸지 않는다.
- 감시/조회/분석은 제한된 작업 큐와 요청 빈도/동시성 제한을 사용한다. 같은 채널의 쓰기는 직렬화하고
  오류/제한 응답에는 백오프한다. DOM 전체를 반복 스캔하거나 무제한 요청/재시도를 하지 않는다.
  OCR/AI/무거운 문자열 처리는 가능한 Worker 및 분할 실행과 작업량/시간 제한으로 입력 응답을 보호한다.
  부하가 커지면 자동 처리량을 줄이거나 일시 중지한다. 메인 스레드의 긴 동기 처리를 허용하지 않는다.
- 사용자는 평소처럼 사이트를 이용할 수 있어야 하며, 긴급 중지/감시 OFF는 처리 대기열에도 적용한다.
  이미 전송한 서버 요청을 취소로 원복했다고 가정하지 않고 결과 재조회와 상태 기록을 수행한다.

여기서 백그라운드는 **사용자 화면을 점유하지 않는 페이지 내 비동기 실행**이다.
일반 Userscript는 브라우저 종료/실행 페이지 종료/탭 폐기/PC 절전 동안 상시 실행을 보장하지 않는다.
다른 탭 사용 중에도 브라우저의 타이머 제한/탭 정지로 처리가 지연될 수 있으므로 정확한 주기나 즉시 처리를 약속하지 않는다.
재개 시 최신 신고/설정/권한/글 상태를 다시 확인하고, 밀린 작업을 한꺼번에 발송하지 않는다.
이 한계는 별도 서버나 다른 확장 구조를 도입한 것으로 숨기지 않고 설정/운영 안내에 설명한다.

Phase 1에서 백그라운드 조치/결과 읽기의 가능성을 조사하고, Phase 4/6/8에서 감시·분석 부하를 제한한다.
Phase 5에서 조용한 안내/선택적 알림을, Phase 7/9에서 무방해 조치/중단/재개와 사용 중 응답성을 검증한다.
인수 기준은 `TEST_PLAN.md`의 `BKG-*`다. 현재 백그라운드 이동 기능은 구현/실사이트 검증 전이다.

## OP-08. 버튼 표시·고정 및 전용 관리자 화면

이 절은 사용자가 추가로 승인한 UI 보완이며, 구현 범위는 화면 설정에 한정한다.

- 최초 상태는 버튼 표시 ON/위치 고정 OFF다. 기존 좌표를 유지하며 표시/고정 값을 별도 버전으로 검증·저장한다.
- 위치 고정 ON이면 드래그/Alt + 방향키/기본 위치 초기화를 막되 버튼 클릭과 설정 열기는 허용한다.
  화면 크기 변경 시 보이는 영역으로 배치하는 기존 동작은 유지한다.
- 표시 OFF이면 버튼과 간이 패널을 숨긴다. 새로고침 후에도 유지하며 숨김은 감시/자동 이동 설정을 변경하지 않는다.
  현재 감시/자동 이동 기능 자체는 미구현이고 OFF다.
- 관리자는 간이 패널의 ‘관리자 설정 열기’, Alt + Shift + G 또는 설치된 스크립트의
  Tampermonkey 메뉴로 전체 화면 설정을 연다. 숨겨진 상태에서도 단축키/메뉴는 복구 경로로 남긴다.
- 관리자 화면은 사이트 내 Shadow DOM UI이며 별도 서버/아카라이브 관리자 URL을 만들지 않는다.
  사이트 권한을 증명하거나 제공하지 않고 화면 설정과 현재 미검증 상태만 표시한다.
- 사용자 요청에만 열고 새 탭/페이지 이동/네트워크 요청을 하지 않는다. 닫기/Escape는 가능한 이전 포커스로 돌아간다.
  열린 동안 Tab을 설정 화면 안에 유지하고 IME 조합 중에는 전역 단축키로 끼어들지 않는다.
- 저장 차단 시 현재 화면에 적용하고 영구 저장 불가를 안내한다. 손상된 표시/고정 자료는 안전한 기본값으로 복구한다.
  같은 origin/브라우저 범위의 UI 선호이며 계정·채널 운영 설정이나 다른 탭 즉시 동기화 기능은 아니다.
