# 사용자 정의 탐지 주제·예외·이미지 링크 계약

기준일: **2026-10-24 (Asia/Seoul)**. Specification 1.2의 추가 요구사항.
현재 Phase 0에는 아래 기능이 없다. 이 문서는 후속 구현/인수 기준이며 Phase 승인 변경은 아니다.
채널 선택/신고 집계/복수 관리자 안전 조건은 [OPERATING_REQUIREMENTS.md](OPERATING_REQUIREMENTS.md)를 따른다.

## TOP-01. 광고 외 주제까지 사용자 정의

- 사용자는 코드 수정 없이 채널별 주제를 추가/수정/삭제하고 켜거나 끌 수 있어야 한다.
- 광고 주제 예시: **리딩방**, **쇼핑몰 링크**. 광고 외 주제 예시: **거래글**, **스포일러**.
  예시는 강제로 활성화하거나 특정 대상 탭과 함께 자동 등록하지 않는다.
- 이름만 등록한 주제는 판별 규칙이 없는 초안이다. 이름을 이해하는 분류기가 자동 생성된다고 안내하지 않는다.
- 각 주제는 키워드/실행 제한 있는 정규식/URL 호스트·경로/이미지 링크/OCR·QR 등
  지원되는 근거 조건을 사용자가 구성하고 테스트할 수 있어야 한다. OCR/QR은 해당 엔진 활성 시에만 사용한다.
- 광고 모델의 결과를 모든 사용자 주제의 판정으로 재사용하지 않는다. 로컬 AI는 해당 주제/한국어
  성능과 모델 지원 범위를 검증했을 때만 선택적으로 연결한다.
- '차단할 주제'는 정책상 검토/글머리 이동 대상으로 지정한다는 뜻이다.
  광고 외 주제를 추가해도 자동 게시글 삭제/댓글 삭제/이용자 차단은 구현하지 않는다.

주제 설정에 필요한 항목:

- `topicId`, 표시 이름, 설명, 광고/사용자 정의 구분, 활성 여부, 적용 채널.
- `rules`: 키워드/정규식/도메인·경로 등 조건과 검사 출처(제목/본문/일반 링크/이미지 링크/OCR/QR).
- 규칙별 가중치/증거 그룹, 주제별 검토·이동 점수와 최소 독립 근거 수.
- `exceptions`: 범위/일치 조건/처리 효과가 명확한 예외 목록.
- 신고 호출 조건: 채널 기본값 상속 또는 주제별 호출어 재설정.
- 처리 방식: 비활성/시뮬레이션/관리자 검토/조건 충족 시 이동. 자동 이동은 명시적으로 켜기 전 OFF.
- 이동 대상: 해당 채널의 사용자 선택 대상 상속 또는 주제별로 선택한 검증된 대상 탭.
- 설정 버전/검증 상태/합성 입력의 테스트 결과.

신고 호출 조건과 게시물 탐지 규칙은 별개다. 광고 주제의 기본 신고 키워드는 계속 `광고`지만,
다른 주제는 `거래`, `스포일러`, 공통 호출어 `검토` 등으로 사용자가 지정할 수 있어야 한다.
주제명/신고 내용은 게시글 자체의 탐지 근거에 가산하지 않는다.
신고 기반 처리 흐름은 유지하며 이 보완이 신고 없는 모든 글의 자동 처리를 뜻하지 않는다.
사이트의 1회 신고 제한과 현재 신고 수를 사용하고 별도 신고자 중복 집계는 만들지 않는다.
주제별 호출 수를 별도로 평가해도 서로 합산해 사이트 총수를 부풀리지 않는다.

## TOP-02. 예외 범위와 우선순위

- 주제별로 허용 키워드/정규식/도메인·경로/검증 가능한 작성자 식별값 등의 예외를 추가/수정/삭제할 수 있다.
- 예: 쇼핑몰 주제를 탐지하되 특정 공식 상품 안내 링크는 해당 주제에서 제외하거나 검토만 수행.
  리딩방 피해 사례/경고 글은 광고 유도 글과 구별할 예외 조건으로 테스트한다.
- 예외 효과는 `해당 규칙 근거 제외`, `해당 주제 자동 처리 제외`, `관리자 검토로 전환` 등으로 명시한다.
  단순 감점과 자동 이동을 막는 예외를 혼동하지 않는다.
- 예외는 주제별 범위가 기본이다. 한 주제의 허용 도메인이 다른 모든 주제를 자동 면제하지 않는다.
  채널 전체 예외를 제공한다면 사용자가 그 범위와 자동 처리 차단 효과를 명시적으로 선택해야 한다.
- 판정은 적용 가능한 예외와 불확실성을 확인한 뒤 이동 가능성을 계산한다.
  예외와 탐지 규칙이 동시에 맞아도 점수만으로 예외의 자동 처리 금지를 뒤집지 않는다.
- 예외 정규식 오류/시간 초과/필수 입력 누락은 '예외 없음'으로 처리하지 않는다. 해당 자동 조치는 중단/검토한다.
- 사용자에게 일치한 규칙과 적용 예외/범위/최종 사유를 함께 표시한다.
- 주제/규칙/예외를 변경·삭제·비활성화하면 해당 정책 버전의 대기 작업을 취소 또는 재검토한다.
  변경 전 분석으로 이동하거나 처리 완료 글을 새 규칙에 따라 자동 재이동하지 않는다.

## TOP-03. 주제별 판정과 복수 일치

- 결과는 topicId/규칙/근거/출처/예외/점수/검증 상태를 포함한다. 비광고 주제는
  '거래글 위험 점수'처럼 주제에 맞게 표시하고 광고 판정이나 통계적 확률로 오표기하지 않는다.
- 점수/근거는 주제별로 계산한다. 서로 다른 주제의 낮은 점수를 더해 이동 임계값을 넘기지 않는다.
- 같은 목적지 링크를 텍스트/이미지/OCR에서 반복 발견해도 동일 출처의 같은 근거를
  여러 독립 근거로 부풀리지 않는다. 복수 근거 요구와 인용/경고 문맥 검토는 계속 적용한다.
- 한 주제의 예외는 다른 주제의 결과를 없애지 않는다. 단, 채널 전체의 자동 처리 차단 예외는 그 범위를 따른다.
- 이동 가능한 여러 주제가 서로 다른 대상 탭을 요구하면 충돌로 표시하고 관리자 검토로 보낸다.
  단순 최고 점수나 목록의 첫 항목을 근거로 임의 선택하지 않는다.
- 여러 주제의 대상이 같으면 조건을 통과한 결과를 한 번의 조치로 묶고 근거/주제를 함께 기록한다.
- 글의 기처리/중복 이동 키에 topicId를 넣어 주제 수만큼 이동시키지 않는다.
  기존 채널/대상 수준 중복 방지와 타 관리자 이동 존중 원칙을 유지한다.
- 자동 이동에는 주제 설정 외에 기존 신고/권한/모드/설정 버전/최신 상태/긴급 중지 조건도 모두 필요하다.

## LNK-01. 사진에 걸린 실제 하이퍼링크

다음 항목을 별개 출처로 수집/표시한다.

1. **이미지에 걸린 링크:** 게시물 내용 영역에서 클릭 가능한 이미지의 링크 목적지.
   예를 들어 `<a href="https://shop.example/item"><img src="https://cdn.example/banner.png"></a>`는
   이미지 파일 위치가 cdn.example이고 실제 클릭 목적지는 shop.example이다. 예시 호스트는 합성 값이다.
2. **이미지 파일 주소:** src/currentSrc/srcset 등 실제 표시 이미지의 위치. 이것을 클릭 목적지로 오인하지 않는다.
3. **이미지 픽셀 속 주소/문구:** OCR로 추출하며 이미지에 실제 링크가 걸려 있다는 증거는 아니다.
4. **QR에 담긴 주소:** QR 모듈로 추출하며 위 출처와 구별한다.

이미지 링크 추출은 DOM 기반이며 **OCR·QR이 OFF여도 동작해야 한다**.
주변 링크와 실제 연관된 img/picture 등의 역할은 확인한 사이트 구조를 근거로 구현한다.
사이드바/사이트 배너/프로필 사진은 게시물 내용과 섞지 않는다. 페이지 전체의 링크를 무차별 수집하지 않는다.
반환할 값은 링크 원문/해석된 목적지 URL/이미지 주소/게시물 내 위치/출처/연관 근거/상태이며,
로그/내보내기에는 필요 없는 URL 쿼리의 민감 정보나 토큰을 남기지 않는다.

- 상대 URL은 확인된 문서 기준 URL로 해석하고 호스트·경로 규칙에 입력한다.
  잘못된 주소와 HTTP(S) 외 실행 가능한 링크는 열거나 실행하지 않는다.
- 링크 추출과 도메인 예외 검사는 URL을 실제 방문하지 않고 수행한다.
  외부 목적지 방문/다운로드/로그인/리다이렉트 추적을 자동 실행하지 않는다.
- 도메인 일치는 실제 호스트 경계로 판정하고 하위 도메인 허용 여부를 구별한다.
  `shop.example.evil.example`을 `shop.example` 허용 예외로 취급하지 않는다.
- 이미지가 외부 링크를 가진 사실, 외부 CDN 사용, 이미지 확대용 링크만으로 광고/다른 주제를 확정하지 않는다.
  사용자 설정 주제 규칙과 예외를 평가해 근거로 사용한다.
- onclick/숨겨진 스크립트로만 목적지가 만들어져 검증된 href를 읽을 수 없다면
  링크 없음으로 확정하거나 클릭해 알아내지 않는다. `unsupported`/미확인 상태와 검토 사유를 남긴다.
- 반복 링크/썸네일과 원본 링크는 제한된 수량/길이/시간 내에 검사하고 근거를 중복 가산하지 않는다.

## 확인 사례: 후기·추천 형식의 투자 홍보

- 2026-10-24 사용자가 제공한 화면의 글을 다른 관리자가 광고로 판단해 이미 삭제했다고 확인했다.
  이 사례의 광고 정답 표시는 `user-confirmed`다. 에이전트가 원문/삭제 이력/계정 정보를 직접 조회한 것은 아니다.
- 이 사례는 후기형 홍보의 **광고 양성 사례**로 취급한다. 제공된 화면에 URL이나 노골적인
  광고 키워드가 보이지 않는다는 이유로 정상 글로 제외하지 않는다.
- 합성 재현 구조: 투자 손실·불안 경험 → 특정 인물/업체의 글로 자신감 회복 →
  친절한 투자 안내에 대한 칭찬 → 함께 참여하자는 권유. 실제 인명은 규칙/블랙리스트에 자동 등록하지 않는다.
- 사용자는 이런 작성자에게 작성글이 5개 미만이거나 없는 경향이 있다고 설명했다.
  향후 검증된 활동 자료의 0~4개 구간을 보조 신호로 평가한다. 관측 범위(채널/전체), 현재 글 포함 여부,
  자료 완전성을 구별하고 조회 실패/비공개/삭제로 보이지 않는 글을 실제 0개로 추정하지 않는다.
  게시글 수만으로 가입 시기나 광고 여부를 확정하지 않는다.
- 새 글에는 추천 대상/참여 유도/문맥을 함께 평가하고 정상 후기·단순 감사·피해 경고·인용을 대조한다.
  단일 표현 일치, 활동량 부족 또는 기존 광고와의 유사도만으로 자동 이동하지 않는다.
  기존 신고/독립 근거/예외/권한/모드 검증 조건은 유지한다.
- 이미 삭제된 이 사례는 추가 이동/복원/재시도 대상이 아니다. 현재 상태의 삭제/조회 불가를
  우리 이동 성공으로 기록하거나 단순 조회 실패만으로 타 관리자의 삭제를 확정하지 않는다.
- 화면의 개인 이름/실제 신고자 자료를 Fixture나 외부 AI로 복사하지 않고 합성 사례로 검증한다.
  이는 후속 탐지 요구사항이며 현재 실행 엔진을 구현한 것은 아니다.

## 구현 시점과 인수 기준

- Phase 1: 게시물 내 일반/이미지 링크, 이미지 확대/실제 외부 이동 구분, picture/지연 로딩 등 실제 구조 조사.
  미확인 선택자를 추측하지 않고 합성 Fixture로 경계를 검증한다.
- Phase 2: 주제별 규칙·예외·점수·일반/이미지 링크 URL 판정의 순수 엔진 계약과 Mock 테스트.
- Phase 4: 검증된 게시물 수집 어댑터에서 이미지 링크 자료와 주제별 신고 호출을 연결한다.
- Phase 5: 주제/규칙/예외 CRUD, 채널별 선택, 출처별 미리보기/합성 입력 테스트와 정책 버전 관리 UI.
- Phase 6: OCR/QR에서 얻은 자료를 별도 출처로 결합한다. 이미지 하이퍼링크 지원을 이 단계까지 미루지 않는다.
- Phase 7/9: 충돌/예외 우선/정책 변경/기처리/권한/다중 관리자/유한 실행 시간의 회귀 검증.

후속 인수 사례는 [TEST_PLAN.md](TEST_PLAN.md)의 `TOP-*`, `LNK-*`를 따른다.
현재 주제 설정/예외/이미지 링크 수집·판정 기능을 구현하거나 실사이트에서 검증하지 않았다.
